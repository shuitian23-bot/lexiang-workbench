联想乐享
WHY · 问题

今天网购一台电脑，要自己走完七步

打开电商网站 → 搜「笔记本」→ 几千个结果 → 加筛选、按价格排序 → 一个个点开看参数 → 翻评价 → 跨店比价 → 最后再判断要不要等大促。

1决策成本全在用户

搜索、筛选、比较、验证、择时——每一步都要用户自己动手、自己判断，平台只负责「陈列」。

2选择过载，难以取舍

「笔记本」搜出几千个 SKU，参数、配置、价格档位交叉，不熟悉参数的用户难以判断哪款适合自己。

3有了对话框，不知道怎么开口

就算给了 AI 入口，真实场景里相当一部分人第一句话就卡住——需求在脑子里，说不成一句完整的话。

WHY · 机会

大模型把交互方向倒了过来

传统电商 · 人找货

  • 自己搜、自己筛、自己排序
  • 逐个比参数、翻评价、比价
  • 领券规则自己研究
  • 下单前反复比较、难以决定

乐享 5.0 · AI 帮你办

  • 用户只做两件事：说出需求、确认决策
  • 推荐、对比、选款交给 AI
  • 优惠自动领取、自动叠加
  • 过程全程可见、可打断

不是给电商加一个聊天窗，而是把「导购员 + 跑腿员」装进产品：对话是入口，操作闭环才是主体。

HOW · 方法论 2

一句话进来，三条通道分流

用户开口说一句话
① 本地规则高频确定性指令（开页 / 切站 / 认证 / 人工 / 序号下单）本地正则识别直接执行毫秒级 · 零模型成本 · 断网可用
② 小模型意图路由口语化操作（“嗯…那就这台吧，优惠都领了”）由轻量模型判定意图，结构化输出交前端执行秒级 · 泛化口语
③ 官方 SKILL + 自研编排推荐 / 知识 / 会员等复杂能力调联想官方 AI；自研编排负责执行与兜底能力最全
过程全程透明：「联想乐享正在判断 → 已判断 → 正在调用 XX SKILL → 已完成」思考时间线实时可见，答完自动折叠成一行。快指令不进大模型，等待与成本都省下来。

HOW · 方法论 3

预判用户的预判：替用户把需求问清楚

输入引导漏斗

只打两个字「推荐」，引导自己弹出来：
想买什么（品类）→ 用来做什么（用途）→ 预算多少 —— 逐级点选，自动拼成一句完整需求，用户全程没打过一个长句。

高频场景词秒弹引导

「以旧换新」「国补」「清灰」「认证」……打出词就弹对应引导选项。这些词全部来自六万条提问的聚类结果——用户还没想好怎么问，选项已经替他问了。

「让用户会提问」这件事本身就是产品能力的一部分——引导不是装饰，是转化的第一级漏斗。

HOW · 方法论 4

对话即操作：说话 = 点击

所见即所得

左边对话、右边页面联动——AI 说到哪，右侧展示到哪：推荐出商品墙、对比开参数表、下单弹确认单，用户不用在对话和页面间来回切。

口语直达闭环

「打开拯救者Y9000P」「第三个不错，下单吧」「回首页」「全屏」——导航、比较、下单、窗口控制全部一句话完成，序号按用户屏幕上看到的顺序数。

领券自动化

下单前自动核对可用优惠：国补、平台满减、会员折扣自动领取叠加，省多少钱当场展示。

服务也是一句话

「认证」秒回三类身份选择直开表单；「人工」秒切专属客服模式——服务入口不藏在菜单里。

HOW · 方法论 5

多步任务链：一句话全权代买

「预算一万到两万，玩游戏用，帮我挑一款好的」——系统自动走完 官方推荐 → 打开对比 → 智能选款 → 生成订单 四步，每一步以 SKILL 卡片实时呈现，右侧画面同步联动。

过程可视

每个 SKILL 的调用与结论（找到几款 / 选中哪款 / 为什么）逐行展示——AI 不是黑盒。

兜底不卡死

官方超时 / 超预算 / 空结果，自动降级到自营货盘按需求续跑，任何分支都有下文、有解释。

决策留给人

链的终点是「确认支付」弹窗——AI 干活，人拍板，全程可打断可反悔。
