# 列表筛选区布局与框内提示合同

2026-11-09 确认框内提示，2026-11-24 补充白底控件、按末行排布操作区与两行折叠规则。

## 适用范围与优先级

用于门户工作台 PM 新增页面、UI 原型和研发中的列表、看板、配置列表的查询/筛选区域，包含展开后的高级条件。本合同覆盖历史“筛选标签持久显示”“多个日期必须显示外部标签”以及默认28px密集筛选的冲突规则；业务录入表单、弹窗/抽屉编辑表单、Skill 创建、权限申请中的上置标签保持原合同。

已确认消费者：GEO整体数据概览的意图选择、协议采购单管理、商品视频配置、活动积分配置、活动积分明细、评价总结、辅助生成的指定筛选区。权限管理既有审批列表暂不迁移；这不是新增其他业务筛选页继续使用上置标签的理由。同一轮已授权的筛选区优化要走查项目中共用同一控件或有同类问题的入口，优先在共用实现修复，并验证代表页面；已定稿页面适用根 Skill 的保护规则。筛选字段、权限、条件值、查询、重置和实时筛选语义沿用原实现。

## 可见排版

- 字段名只在控件内表达，避免上置字段标题与框内提示同时出现。纯白底、细边框，常态不加灰底、彩色底纹、渐变或内阴影。占位文字使用次级文字色。禁用、错误和焦点沿用对应状态。
- 文本框空态写字段名称或可搜索范围，输入后显示用户填写的值。必填字段保持可见的必填标记，仅在格式说明补充了输入限制时才常驻展示。错误按需贴近控件，并保持可访问关联。初始空态也避免重复字段提示和无状态可重置时的额外重置按钮。
- 单选和可搜索下拉在闭合态显示「字段名 · 当前值」，默认如「状态 · 全部」。展开时只显示选项本身，例如「全部」「待审核」。保留 option value 和原有搜索、提交语义。多选沿用已有项的选中、移除和摘要规则。
- 日期未选时，在框内显示“开始日期 / 结束日期”；有多组日期时显示“付款开始日期 / 付款结束日期”等独立明确名称。获得焦点后可显示原生日期编辑段；选中后显示真实日期。保留日历图标、键盘输入、日历选择和日期校验，不能简单依赖原生 date 的 placeholder 属性。
- 日期起止作为一个条件组排布；多组日期已有值时，在各日期组内保留范围名称。
- 常规筛选控件和查询/重置按钮为36px高、13px字、8px圆角，文本水平内距12px；白底、细边框、次级占位色、共享focus ring。选择箭头和日期图标保留右侧空间。不要被继承全局CSS改为10px圆角或28px高度。
- 筛选字段间距12px。内容宽度达到1040px时以四列为基准，720–1039px通常两列，窄于720px一列。线索池等条件密集的页面可按可用宽度和控件的最小可读宽度自适应增列。日期范围作为一项，可跨两列。模块标题与筛选字段标题不同；不为了本规则批量删除独立业务模块标题，也不额外给简单筛选条加“筛选条件”标题。

## 操作区与折叠

- 操作组统一右对齐。以最后一条可见条件行为准。该行只有 1–2 项条件且右侧足以容纳整组按钮时，操作与该行同行，即使前面已有一行。末行有 3 项及以上条件或右侧空间不足时，操作整组另起一行。日期范围按一项计，按实际跨列宽度判断剩余空间。
- 按实际内容宽度让筛选条件优先填满前两行。能放进前两行的条件默认可见。只有条件超出两行时，才显示「展开筛选」或「高级筛选」。两类入口统一用 36px 浅蓝底、蓝字的次级按钮，以「展开／收起」文案表达状态，省去箭头。每个筛选区只保留一个展开入口。页面自带入口时复用该入口；公共布局接管或重新挂载时回收旧入口。收起保留筛选值，高级入口的数量按已生效的高级条件计算。
- 手动查询的顺序为「高级筛选」「重置」「查询」，查询为主按钮。实时筛选保留实时反馈和重置入口。导出默认在结果区工具栏，沿用已生效的查询结果。
- 筛选区与结果区有清晰的卡片边界。使用白底、细边框、12px 卡片圆角及 16px 内边距，普通短筛选条不加重复标题。

## 可访问名称与作用域

- 隐藏的是可见的外部标题，不能删除字段的程序化名称。保留 visually-hidden label、label/for 或 aria-label；开始和结束日期独立命名，范围组用 div/role=group，不用一个label包住两个输入框。
- 选值、清空、加载、禁用、错误、只读及高级筛选展开/收起后，字段语义仍可识别；错误信息继续与对应控件关联。框内底文不能成为唯一可访问名称。
- 不写全局隐藏label、span、input、select的样式，不改壳层或所有表单的默认布局。对项目已有 FilterField 显式传 layout="placeholder"；已有 PointsSelect 只在目标筛选区启用 inline-label。默认 stacked/inset 和普通业务表单保持原样。

## PM 使用方式与参考实现

先检查目标项目已验证组件，优先复用。项目中的 FilterField/PointsSelect 与 Skill 中 FormControl 是映射关系，不应因文件名不同重写全套页面。

Skill参考库中的 FilterBar 为后代 FormControl 提供placeholder布局上下文；FormControl 在普通表单内默认仍为stacked，也支持显式 labelLayout="placeholder"。因此PM复用 FilterBar + FormControl 即得到本合同，字段不能另外叠加上置label。例子见 content-slot-vue-library.md。参考实现是无业务依赖基线，不表示线上或所有项目已迁移。

## 验收

1. 空值、选值、清空和高级筛选展开后均不出现控件上方标题；默认选项不重复字段名，日期底文能区分起止，控件白底且无重复标签。
2. 运行页面测量：控件与查询/重置按钮36px、字号13px、圆角8px；不能只看源码token。原有focus/disabled/error状态及筛选值保持。
3. 目标筛选区外至少检查一个业务录入表单或新增弹窗：上置标签仍可见。核对全局CSS没有新隐藏标签选择器，共享组件的默认消费者不变。
4. 检查桌面宽度及 Agent 挤压后的两行折叠、操作区右对齐、展开后字段值保留和局部表格滚动；若未实际测量，不声明全面响应式通过。
5. 新增或修改内容槽文件运行设计guard及适当工程检查，分别记录本地结果、未覆盖状态和生产验收边界。
