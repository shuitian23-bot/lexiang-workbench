# 组件规范（PC 端 · 乐享 AI 工作台）

当前乐享 AI 工作台里反复出现的组件，统一在这里定义结构、状态、用法。生成页面时优先复用这些，
不临时造样式。视觉细节自动继承 `design-tokens.md`（颜色、字号、圆角、控件高度均走变量）。

**标记**：⊳ 推荐默认（直接可用，可调）；⬅ 需团队决策。

---

## A. 基础交互

### 1. 按钮 Button

层级（一个页面主按钮通常只出现一次）：
- **主按钮 primary**：`--color-primary`(#3370FF) 实底 + 白字。页面主操作。
- **次按钮 secondary**：白底 + `--color-border` 描边 + `--color-text`。取消、返回。
- **文字按钮 ghost**：无底无框 + 主色文字。弱操作（更多、查看）。
- **危险按钮 danger**：`--color-danger` 实底或描边。删除、停止等破坏性操作。

尺寸：`sm` 28px / `md` 36px（默认）/ `lg` 44px，对应 `--control-height-*`。
状态：默认 / hover / 按下 / 禁用(opacity .5) / **加载中**（左侧转圈 + 文字"处理中"，禁止重复点击）。

⊳ 推荐：图标按钮（仅图标，方形）用于表格行操作、工具栏，配 tooltip 说明。
⊳ 推荐：主按钮不强制带图标；只有“新建、导入、下载、同步、启动”等动作能被图标快速识别时才加前置图标。默认圆角使用 `--radius-md`(6px)，不要把后台主按钮做成胶囊。
⊳ 推荐：附件、发送、刷新、关闭、亮暗切换等高频工具操作优先用 icon-only 方形按钮；tooltip 必须在真实页面布局中完整可见，不被顶栏、侧栏、AI 面板、抽屉或输入区裁切。

### 2. 输入控件 Form Controls

涵盖：文本框、数字框、下拉单选、下拉多选、搜索框、文本域、复选、单选、开关、日期/时间选择器。

统一规则：
- 标签在输入框**上方**、左对齐（后台密集表单比左右布局更清晰）。
- 控件高度 = `--control-height-md`(36px)，与按钮对齐。
- 焦点态：边框变 `--color-primary` + `--focus-ring`（主色浅底外发光）。
- 错误态：边框 `--color-danger`，下方红字提示，提示说"怎么改"不指责用户。
- 禁用态：底 `--color-bg-muted`，文字 `--color-text-disabled`。
- 占位符用 `--color-text-tertiary`(#7B7B7B)。
- 日期 / 时间输入默认保留系统日历图标和原生可识别性；hover 只允许做轻量可见度增强，不额外叠加蓝底块、白底补片或第二层方形容器。
- 日期范围组件如果使用 `FROM / TO` 双输入或浮层连接角，连接区域必须与整体容器同底色同层级，不能出现明显纯白补丁、割裂接缝或双层外框。

✅ 必填标记：红星 `*`（标签前）+ "(必填)" 文字 并用，双重提示，关键项尤其明确。
✅ 校验时机：**失焦校验为主，提交时兜底**全表再校验一次。实时校验仅用于"密码强度""字数上限"等需即时反馈的少数场景。

### 3. 下拉菜单 Dropdown / 选择器

触发后浮层用 `--shadow-sm` + `--radius-md`，层级 `--z-dropdown`。
选项 hover 用 `--color-bg-subtle`，选中项用 `--color-primary-subtle` 底 + 主色文字。
长列表（>10 项）内置搜索框；多选项显示勾选框 + 已选计数。

## B. 数据展示（当前项目核心）

### 4. 表格 Table —— 后台最重要的组件

结构：
- 表头：`--color-bg-muted`(#F2F2F2) 底 + `--font-weight-medium` + `--text-xs`。
- 行高：默认 `--row-height-compact`(40px)，可切换常规/舒适。
- 行 hover：`--color-bg-subtle`；选中行：`--color-primary-subtle`。
- 斑马纹（可选）：偶数行 `--color-bg-subtle`。
- 单元格内边距 `--space-2`×`--space-3`；数字/ID 列右对齐 + 等宽字体。
- 操作列固定在最右，用图标按钮 + tooltip 或"更多"菜单。

必须考虑的状态：加载中（**骨架屏**优先于转圈）、空数据（见组件 13）、错误重试。

⬅ 决策（按需勾选，影响表头交互）：
- [ ] 列排序  [ ] 列筛选  [ ] 全局搜索  [ ] 批量选择（行首勾选框 + 批量操作条）
- [ ] 列显隐/拖拽排序  [ ] 行展开（展开看详情/子表）  [ ] 密度切换  [ ] 固定列
- [ ] 分页（推荐：底部分页器，支持每页条数切换）

### 5. 指标卡 Stat / Metric Card（仪表盘用）

运营、GEO、GMV、线索等看板常见。结构：标签（次要文字）+ **大数字**（`--text-3xl` + 等宽）+ 同比/环比（升降箭头，升用 success、降用 danger）+ 可选迷你趋势图。
多卡用栅格并排，卡间距 `--space-4`。

全站中间数据展示区（如运营总览、GEO、在职员工、线索池、搜索后台、风控、数据查询、质量分析）使用统一项目样式：
- 一行 4 张时必须等宽、等高、顶部对齐；使用 `repeat(4, minmax(0, 1fr))` 和 `align-items: stretch`。
- 标准间距：页面标题到 KPI grid `12px`，卡片 gap `14px`，KPI grid 到下一模块 `16px`。
- 页面顶部 KPI、概览指标等主要信息色块使用基于主色 `#3370FF` 推导的四种极浅辅助渐变循环：蓝、青、靛、紫 + 细边框 + 轻阴影；有色辅助色 alpha 必须低于 10%（推荐 2.5%-8%），白色收尾可为 100%，颜色只保留很轻的信息感，不要明显抢眼。下方链路步骤、拆解项、图表容器、表格容器、筛选区、待接口占位块和大面板保持纯白底 + 细边框 + 轻阴影。不要使用语义 wash、普通分类浅红或整排饱和色块。
- 同一 KPI 行不要每张卡都用左侧竖线、顶部粗色条或标签前小圆点点缀。若需要区分类别，优先通过标题、数字层级、分组顺序、辅助文案和图表图例表达。
- 只有页面顶部重点 KPI / 概览指标使用四色浅渐变；卡片内部二级统计块和非主要内容默认白底，避免整页色块过重。该规则必须全站同步，不允许只在某一个模块修正。
- 本地预览若存在模块私有背景色，必须通过共享覆盖层同步到协调多色浅渐变信息底或白色内容容器，不能只改某一页截图里的类名。
- 待接口、空数据、占位数据卡必须与普通数据卡一样使用白底细边框；多个占位卡并排时中间保留 `12-14px` gap，不允许合并成连续色块。
- 内容顺序固定为 label / value / subtext；数字不拉伸、不变形、不因为单位长短导致卡片错位。
- 推荐分类色：主总量用 primary，正向/已认证用 success，驳回/待处理用 warning，新增长或高级指标用 purple。

### 6. 卡片 / 面板 Card / Panel

白底(`--color-surface`) + `--color-border` 描边 + `--radius-md` + `--space-6` 内边距。
后台默认**靠边框分隔**而非重阴影。可带标题区（标题 + 右侧操作）与底部区。

实现约束：
- 同一 grid 行内的 Card / Panel 必须顶部对齐、等高拉伸；不要用相邻卡片 `margin-top` 制造间距。
- 卡片标题区高度、内边距和右侧操作对齐方式必须统一。
- 模块 / 卡片标题必须固定左上角横排展示，不允许被筛选器或按钮挤成竖排；右侧操作、筛选器、说明文字放不下时换到下一行。
- 标题区采用双边对齐：标题组永远作为左侧锚点，右侧按钮、说明、时间筛选、`问 AI` 等操作贴齐模块右边界；拥挤时只让操作区整组换到下一行左对齐，不压缩标题，不让操作漂浮在中间。
- 标题文字、左侧竖线 / 圆点装饰、标签和右侧按钮必须在同一横向基线或视觉中线上；禁止装饰线偏上、标题偏下、按钮另起高度造成错位。
- 多行标题区里如果筛选器、按钮组或 Tab 换到第二行，竖线 / 圆点仍然锚定第一行标题文字的中线，不跟随整个 header 高度居中。
- 标题装饰语义固定：页面内主章节、独立大卡片和跨模块分组标题使用左侧竖线；图表卡、表格卡、列表项、图例/分类项等子内容标题使用圆点。不要同级标题一会儿竖线一会儿圆点。
- 图表卡、表格卡、指标卡混排时，内容区自适应填充卡片；不允许图表在大卡片中显得过小或漂浮。
- 卡片内如果有 Tab、筛选器、按钮组，必须使用独立 header 或 filter row 承载，不要用随意的内联偏移。
- Header 内标题是对齐锚点，filter row 可以换行，不能压缩标题宽度。
- 描边线框型模块在 hover 或 selected 时使用主色描边和轻微主色外环/阴影；不要改成整块高亮背景。页面级 Tab 仍只使用文字色 + 下划线。
- 中间数据区域卡片 / 面板 / 图表卡 / 表格容器 / 链路节点 / 占位卡统一使用轻量 hover：主色浅描边、轻阴影、`translateY(-1px)`、`.14s` 过渡。该效果不作用于 AI 面板、按钮、Tab、表格行和输入框。
- 筛选 chip、时间范围按钮、分段按钮在亮/暗色主题下都必须有足够对比：选中态使用主色底 + 白色文字，未选中态使用当前主题表面色 + 次级文字，禁用态使用弱边框和弱文字；不要依赖互相冲突的内联色值。
- 按钮、时间范围 pill、chip、分段按钮和次按钮统一使用 6px 图文间距、8px 同组间距、12px 横向内边距；高度稳定，文本不换行，不能靠临时 margin 或空格制造对齐。

### 6.1 联动筛选型指标卡

当一组指标卡点击后会改变下方列表、图表或表格时，必须明确设计为筛选控件，不要做成普通静态 KPI。

- 结构：`button` / 可点击卡片，包含 `data-method` 或对应筛选值，使用 `aria-pressed` 表示选中状态。
- 外观：白底、细边框、8px 圆角、12-14px 卡片间距；左侧可用极细方法色 accent，但不要整卡强色填充。
- Hover / focus：使用中间数据模块统一轻量 hover；键盘 focus 保留主色 focus ring。
- Selected：主色描边、极浅主色底、右上或标题旁显示 `筛选中` badge；再次点击当前项清除筛选。
- 标题区：如果卡片会联动列表，标题旁给短提示，如 `点击筛选下方员工列表`。
- 联动反馈：被影响的表格 / 列表标题行显示当前条件，如 `当前筛选: 企业邮箱 · 598 条`，并提供 `清除` 操作。
- 典型场景：在职员工管理的 `认证方式分布`。企业邮箱、劳动合同、个人所得税视频认证、其他材料等 tile 点击后必须同步更新下方员工列表。

### 7. 标签 / 徽标 Tag / Badge

状态标签严格按 `design-tokens.md` 第 2 节的状态色：浅底(`*-subtle`) + 实色文字 + 同色小圆点。
计数徽标（红点/数字）用于通知、未读。`--radius-full` 胶囊形。

### 8. 标签页 Tabs

分隔同一页面的多视图。选中态：主色文字 + 主色底部下划线。
适合详情页（概览/日志/配置/版本等多 Tab）。

实现约束：
- 主 Tab 不使用胶囊背景、浅蓝块或按钮底色；只保留字体颜色、底部分割线和选中下划线。筛选 chip / 时间范围按钮才允许使用描边胶囊。
- Tab rail 要预留完整高度和底部分割线；Tab button 高度稳定，计数文字不改变高度。
- Tab 与下方筛选区、表格区之间使用统一间距，不贴边、不重叠。
- Tab 较多时允许横向滚动或自然换行到下一行，不压缩文字到不可读。
- Tab 必须有真实切换逻辑：点击后 active 状态和对应内容面板同步变化；不得只渲染静态 tab 样式。
- Tab 点击交互必须切换标准 `.active` class，并清理冲突的内联颜色 / 下划线样式；不要只改 `style.color` 或 `style.borderBottomColor`，否则会被全站 tab 规范覆盖。

## C. 反馈与浮层

### 9. 弹窗 Modal / 抽屉 Drawer

- 遮罩：`rgba(0,0,0,.45)`，层级 `--z-overlay`。
- 弹窗：居中、`--radius-lg`、`--shadow-lg`、`--z-modal`，宽度 sm 400 / md 560 / lg 720px。
- 必备：标题 + 关闭按钮 + 底部操作区（主/次按钮靠右）。
- 抽屉：从右滑入，宽度 480~640px，适合**较长表单 / 详情**。

✅ 表单容器规则：简单确认 / 少量字段 → **居中弹窗**；多字段配置 / 详情编辑 → **右侧抽屉**。

### 10. 轻提示 Toast

右上角，`--z-toast`，3 秒自动消失。语义色区分：成功(success)/失败(danger)/警告(warning)/信息(info)，
左侧配对应图标。一次只堆叠少量，避免刷屏。

### 11. 警告条 Alert Banner

页面内嵌的提示块（如"配额即将用尽""有 3 个任务失败"）。浅底(`*-subtle`) + 左侧色条/图标 + 文字 + 可选操作链接。

### 12. 气泡确认 / Tooltip / Popover

- Tooltip：图标按钮、截断文字的悬停说明，深底白字小浮层。
- Popover：点击触发的轻浮层（筛选面板、列设置）。
- 删除等危险操作用气泡二次确认（"确定删除？"+ 危险按钮）。
- Tooltip 展开方向要按位置处理：顶栏和面板头部优先向下，页面底部输入区/页脚优先向上；层级高于卡片、抽屉、AI 面板和 Popover，避免 hover 后被边界截断。
- 下拉小窗、日期时间选择器、筛选 Popover 使用统一圆角、阴影、边框和选中态；不要出现与主系统风格脱节的原生控件样式。

### 13. 空状态 Empty

居中：图标/插画 + 一句说明（为什么空）+ 一个引导操作按钮。
例："还没有模型，点击『创建模型』开始"。

### 14. 加载 Loading

- 表格/卡片：**骨架屏**（灰块占位）优先，体验比转圈高级。
- 局部操作：按钮内联转圈。
- 整页：顶部细进度条 + 内容骨架。

## D. 导航与框架

### 15. 侧栏导航 Sidebar ⊳ 当前项目默认采用

- 宽度 `--sidebar-width`(168px)，可收起到 `--sidebar-width-collapsed`(56px，仅图标)。
- 一级菜单：图标 + 文字；选中项用 `--color-primary-subtle`(#EAF2FF) 底 + 主色文字/图标。
- 支持二级菜单（展开/收起）。
- ✅ **浅色侧栏**：`--color-surface`(#FFFFFF) 底 + 右侧 `--color-border`(#C9C9C9) 分隔线，与内容区靠边框区分；hover 项用 `--color-bg-subtle`。
- 展开态父级目录必须单行展示，长标题省略；不要因为中文标签换行导致目录高度不一致。
- 二级菜单展开按钮使用线性 chevron：收起向右、展开向下。不要使用图片箭头或 `▶` 等文本字符。
- 独立业务域要拆成独立一级目录；例如“客户留言”和“线索管理”必须分开，而不是混在一个泛化的客户目录下。
- 侧栏收起时重新规划展开按钮位置，避免与 Logo 挤压；收起态仅保留图标、tooltip 和清晰的展开入口。
- 当前 Leaibot 收起态默认：品牌小标居中为白底圆角 mark，带细描边和轻阴影；展开按钮是侧栏右边界的小圆形 rail handle，白底、细描边、轻阴影，hover 使用主色浅底。
- 展开态品牌区显示红色联想乐享 logo + 中性灰 `工作台` 胶囊标签；胶囊使用灰底、细描边、次级灰字、11px 字号，避免与红色品牌字撞色。

### 16. 顶栏 Header

高度 `--header-height`(48px)。左：面包屑；右：全局搜索、亮暗切换、AI 助手开关。
顶栏图标按钮保持固定正方形尺寸，亮暗切换、刷新/重新生成等操作使用统一线性图标；hover tooltip 向下展开且不被顶栏裁切。

### 17. 面包屑 Breadcrumb

顶栏左侧，反映当前层级路径，末级为当前页（不可点）。

✅ 侧栏浅色。Logo 固定放在侧栏顶部，与导航同列；收起时显示紧凑小标。顶栏不重复大 Logo，可承载产品名、面包屑或搜索。

## E. 乐享项目专属组件

### 18. 密钥字段 Secret Field

API Key / Token 默认掩码显示（`sk-••••••3a9f`），右侧"显示/隐藏"眼睛 + "复制"按钮。
值用等宽字体。复制后给 toast 反馈。**绝不默认铺明文。**

### 19. 代码 / 日志 / JSON 面板

深底(`--code-bg` #1A1A1A) + 等宽 + 可滚动 + 右上"复制"。日志按级别上色(debug/info/warn/error)，
支持按级别筛选。JSON 可折叠层级。

### 20. 进度 / 配额条 Progress / Quota

训练进度、Token 用量、存储配额等。进度条用主色填充；配额接近上限(如 >85%)变 warning，满变 danger。
配文字百分比/数值。

### 21. 分步配置 Steps / Wizard

创建模型、配置任务等多步流程。顶部步骤条（已完成=主色对勾，当前=主色，未到=灰）。
每步底部"上一步/下一步"，最后一步"提交"。

### 22. 用户/角色 与 头像 Avatar

### 23. 右侧 AI 助手 Panel

当前项目固定使用右侧 AI 助手，不要设计成临时弹窗或普通聊天浮层。

- 默认宽度 `380px`，打开时独立固定在右侧；关闭时宽度为 0；可拖拽扩宽，最大约 `492px`。
- 顶栏 AI 助手开关只在面板关闭时显示；面板打开后，标题区承担开关状态。
- 标题区：圆形助手头像 + 在线绿点 + `AI 助手` 标题 + 短副标题（如 `运营协助`）在左；设置、新对话、历史、收起等 4 个 icon-only 操作在右。副标题必须短，避免与图标重叠。
- 当前项目头部定稿：头像 + 在线点 + `AI 助手` + 浅蓝关注胶囊 `正在关注:{当前二级标题}`；右侧 4 个 icon-only 操作依次为 管理技能 / 新开会话 / 历史对话 / 收起 AI 助手。第三个必须是历史对话，不是更多菜单。
- `正在关注` 胶囊必须与左侧导航当前二级标题同步，页面切换、搜索跳转、AI 跳转、URL `page=` 直达时都要更新，不允许固定写成 `运营总览`，也不要拼接父级目录。
- 面板内部左右 gutter 使用 `16px`；消息区 `18px 16px 16px`，输入区 `10px 16px 12px`。
- 当前确认版默认态欢迎语使用普通文档流，不做数据看板；文案固定为：`你好！我是乐享 AI 助手。你可以在底部输入框里直接描述要完成的运营任务，例如查数据、生成报告、配置商品或查询知识库。涉及写入或发布时，我会先展示影响范围并等待确认。`
- 当前确认版默认态内容只展示紧凑推荐问题卡，例如 `工作台说明`、`生成报告`、`查询知识库`；暂不展示 `今日速览`、DAU / GMV 指标、异常卡或最近对话。
- 对话态：顶部居中显示口径胶囊 `已引用:运营总览 · 最近 1 天`；用户消息右对齐蓝渐变实底；AI 回复使用白卡结构化呈现，结论前置。
- 洞察结论卡 `.ai-insight-card` 是默认分析卡模板：单一白色卡片背景，无最外层阴影和双边框。当前版本先不展示内层瓶颈大数字面板，只保留 `已引用` 胶囊、结论正文、主次操作和来源标签；后续需要大数字时再按具体业务场景单独启用。
- 中段是一段解释文字，正文和 query 文本保持同级字级（约 13px、常规字重）；强调健康指标用绿色，瓶颈/低转化用橙色，只高亮必要短语。
- 当前版本已移除旧的 `登录 / 互动 / 下单` 三段链路小模块；不要在默认 AI 洞察卡里重新加回这一整块。
- 操作区当前顺序固定为：`展开报告` 主按钮在左，`查看明细` 次按钮在中，`优化建议` 次按钮在右。`展开报告` 可带一个前置装饰 icon；`优化建议` 不带 icon，按钮样式和 `查看明细` 保持一致。
- 底部来源 chips 使用纯色填充胶囊，不使用描边、不使用前置线性图标。底部反馈区与上方内容之间只保留一条极浅分割线。
- 洞察卡不要退回到普通条形漏斗列表；正文必须结论先行，数据面板若启用也只能作为辅助信息，不能挤压正文阅读。
- 长篇报告态：AI 面板只展示统一结论卡片 `.ai-result-card`，包含线性文档 icon、标题、简短摘要、标签、`保存` 和 `展开查看`。标题使用 `当前页面 · 真实报告主题`，例如 `运营总览 · 购买转化原因分析`。完整长报告通过 `.workspace-tabs` 临时页签进入中间内容槽，不在右侧面板内展开全文。
- 临时页签 `.workspace-tabs` 位于面包屑/顶栏下方、内容槽上方；无临时报告时隐藏。第一个 tab 是当前导航页面，后续 tab 标题跟随实际页面和 AI 任务主题，选中态使用文字加粗 + 主色 3px 下划线，不使用整块高亮。页签支持关闭、多开和保存态徽标。
- 推荐问题卡片普通字重，约 `58-61px` 高，卡片间距 `10px`。
- 快捷/项目标签放在底部输入区上方并与输入框共用一个圆角边框组合件，标签条在上、输入行在下，中间 0.5px 分割线。
- 标签条桌面端为单行横向滚动 pill，左右两端有箭头；支持箭头点击、鼠标拖动、触控板横向滑动和键盘方向键。窄屏退化为下拉选择器。
- 输入区：附件 icon-only 方形按钮 + 多行 textarea + 蓝色发送 icon-only 方形按钮。空输入时发送按钮置灰；Enter 发送，Shift+Enter 换行。
- 附件、发送、刷新、关闭、亮暗切换 tooltip 必须完整可见，不被容器裁切。

### 24. 账号工作区 Popover

左下角用户信息点击后打开账号工作区入口。它不是普通个人资料菜单，承载平台侧 PM / 管理员高频入口。

结构：
- 触发区：头像、用户名、角色、退出操作；点击用户信息区域打开 Popover，点击退出不触发 Popover。
- Popover：白底、细边框、10-12px 圆角、轻阴影，靠近侧栏底部弹出；侧栏收起态从右侧弹出。
- 内容卡：`创建 Skill`、`Skill Hub`、`权限管理` 三张纵向卡片，每张包含 icon 容器、标题、说明。
- 关闭：右上角 icon-only 关闭按钮；点击外部关闭。

规则：
- `创建 Skill` 是主入口，可用主色浅底或 primary 变体突出，但不要整卡强蓝。
- `权限管理` 若未开放，说明文案写“敬请期待……”，不可伪装成可操作已完成页。
- Popover 层级高于侧栏、内容卡和 AI 面板，但低于全局确认弹窗。
- 三张卡片保持同高节奏、文字不溢出，说明文字最多 2-3 行。

## G. 文案呈现约定（UI 相关）

仅收录与"界面如何呈现文字"直接相关的部分；完整的文案口吻、术语表、措辞规范属于
内容/产品写作范畴，不在本 UI 规范内。

### 微文案样式
- **占位符 placeholder**：给示例而非重复标签（如搜索框写"搜索模型名称或 ID"），用 `--color-text-tertiary`(#7B7B7B)。
- **帮助文字 helper**：复杂字段下方一句说明，`--text-xs` + 次要色 `--color-text-secondary`。
- **错误文字**：控件下方，`--text-xs` + `--color-danger`，紧跟出错控件。

### 提示语的视觉结构（呼应组件 11/13/14）
- 空状态：图标/插画 + 一句说明 + 一个引导操作按钮，居中。
- 错误提示：面向"用户能做什么"；技术细节（堆栈、错误码）折叠进"详情"，不顶在界面上。
- 成功/失败反馈：Toast 右上角 + 语义色图标。

### 文字排版细节
- 中英文之间留一个空格，提升可读性。
- 中文用全角标点。
- 英文专有名词保持官方写法：GPU、API、JSON、Token、URL 等。

### 数据显示格式（呈现层）
- **ID / 密钥 / 哈希**：等宽字体 `--font-mono` + 可复制 + 过长截断（中间省略）。
- **大数字**：千分位显示 `1,280,500`（token/调用量等）。
- **日期时间**：`2026-06-03 14:30`（24 小时制）；列表里可用相对时间"3 分钟前"。
- **百分比 / 时长**：`85%` / `12 分钟`，用于配额、进度、任务耗时。
