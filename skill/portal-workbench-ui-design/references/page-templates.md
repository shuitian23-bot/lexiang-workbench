# 页型模板

本文件规定当前乐享 AI 工作台常见页面的标准结构。生成或评审页面时，先判断页型，再套模板。

## 1. Dashboard / 概览页

适用：门户首页、运营总览、Query 分析、质量分析、流量分析、GMV 分析、GEO 看板、线索看板。

结构：

1. 页头：标题 + 描述 + 时间范围筛选 / 刷新。
2. 指标卡行：3~4 个 Stat Card，自适应栅格。
3. 图表区：趋势图 / 分布图 / 配额图；优先使用 `--chart-*`、`--chart-seq-*` 和语义图表 token。
4. 列表区：近期任务、异常告警、调用 Top 项，使用紧凑表格。
5. 告警条：如有配额预警或失败任务，放在页头下方。

规则：
- 指标卡数字用等宽字体和千分位。
- 图表不要过度装饰，网格线用 `--chart-grid`，坐标轴用 `--chart-axis`。
- 图表优先单色阶或协调的中低饱和色板，并保证类别辨识度；普通分类不要拼接高饱和原色，强红只用于失败、异常、风险等警示状态。
- 中间数据展示区的视觉规则必须全站复用：页面顶部 KPI、概览指标等主要信息色块使用基于主色推导的蓝、青、靛、紫四种极浅辅助渐变循环、细边框、轻阴影，有色辅助色 alpha 低于 10%（推荐 2.5%-8%），白色收尾可为 100%，颜色只做很轻的信息底；下方链路步骤、拆解项、二级统计块、图表卡、表格卡、筛选区、待接口占位和大面板保持白底；不要只在一个模块局部覆盖。
- 告警类信息用 Alert Banner，不要混入普通卡片标题。

### 门户首页变体

门户首页是工作台入口页，仍属于 Dashboard / 概览页，但不使用营销 hero。

结构：
1. 轻量页头：`门户工作台` 标题 + 1 句能力说明 + 右侧 `管理技能包` / `创建 Skill` 操作。
2. 能力卡：4 张等宽卡片，说明 AI 助手、运营分析、Skill 创建、技能包管理等核心入口。
3. 常用入口：白底列表按钮，左侧业务名，右侧短说明，点击跳转对应页面。
4. 基础流程：4 步流程卡，使用小号数字圆点和简短说明。

规则：
- 当前确认版左侧导航不展示 `首页` 父级目录；用户通过左上 Logo 返回门户首页，面包屑仍可展示 `首页 / 门户工作台`。
- 本期不展示 `今日工作流 / 4 个核心域联动` 面板；不要用旧工作流渐变面板填充首屏。
- 首屏必须是可操作的工作台，不做大图、口号、营销 CTA 或装饰插画。
- 能力卡和流程卡使用白底、细边框、8-12px 圆角和轻 hover；不要使用大面积强色块。
- 常用入口必须保留真实页面跳转，不只展示静态文字。
- 默认打开右侧 AI 助手时，首页布局要能在 AI 面板挤压下自然换列。

### AI 临时报告页签

触发来源：仅由右侧 AI 对话中的长篇数据、解读报告、复盘、日报/周报/月报或结构化分析触发；普通左侧导航不使用该页签承载业务页面。

位置：存在临时报告时，在顶栏面包屑下方、`.page-content` 上方显示一条 `.workspace-tabs`。无临时报告时完全隐藏，不占高度。

结构：第一个 tab 为当前导航页面，例如 `运营总览`；后续 tab 标题只放简短任务主题，例如 `购买转化分析`，不要把页面名、`AI 报告`、编号、来源时间等都堆进页签。左侧带主色小星标，右侧关闭按钮统一 18px 图标按钮，保存后显示 `已保存` 小徽标。

内容：临时报告打开后，中间内容槽渲染完整报告页，包含页头、保存 / 下载 / 返回页面操作、浅主色报告摘要 hero、3 张关键信息指标卡、目录侧栏、结论摘要和分段正文卡片。正文必须将长 markdown 拆为结构化章节，不要在摘要下方再次原样堆出整段 markdown。报告页不改变左侧导航选中状态和面包屑父子关系。

版式：临时报告内容必须继承普通导航内容槽的宽度和字号，随中间可用区域自适应填满，直接容器使用 `width:100%`、`min-width:0`、`max-width:none`，不要固定窄宽或居中形成大面积空白。标题和副标题必须直接复用正常内容槽的 `page-title / page-desc` 层级。当前项目运行态以 19px 标题、13px 说明为准；卡片标题 14px，正文 13px，关键数字 18px 左右。不要把报告页做成独立大字号阅读器。标题层级最多保留两处：短页签标题 + 内容主标题；hero 只承载摘要和标签，不重复主标题。

背景：内容槽允许使用基于主色的极浅横向渐变，但必须连续、自然、无硬分割；不要使用固定高度 `background-size` 色带、1px 分割线、高光线或突然回灰的断层。渐变只作为很轻的画布层级，不能变成大面积饱和背景。

交互：从 AI 结论卡展开报告、切换临时页签或返回基础页面时，中间内容槽应滚动到顶部，确保标题、页签和 hero 首屏可见。

多开对比：同一 AI 会话可打开多个报告 tab；点击基础页面 tab 回到当前导航页面，报告 tab 保留直到关闭。

副标题文案：临时报告头部副标题只承担来源说明、页面来源和时间，不再额外提高字级或字重。视觉上必须与普通页面的 `page-desc` 保持一致，不能因为切换到报告 tab 出现“副标题更大、更粗、更蓝”的跳变。

## 2. List / 表格列表页

适用：认证审核、留言工单、线索池、员工列表、知识上传记录、来源明细。

结构：

1. 页头：标题 + 说明 + 右侧主操作。
2. 筛选栏：搜索框 + 筛选器 + 重置；复杂筛选可折叠“高级筛选”。
3. 批量操作条：选中行后出现。
4. 表格：紧凑行高、操作列固定右侧。
5. 分页器：底部右对齐，支持每页条数。

规则：
- 一个页面主按钮通常只出现一次。
- 表格状态必须覆盖加载、空、错误、无权限。
- 行内危险操作必须二次确认。

## 3. Detail / 详情页

适用：留言工单详情、线索详情、认证审核详情、员工详情、知识条目详情。

结构：

1. 页头：返回 / 面包屑 + 对象名 + 状态标签 + 右侧操作。
2. Tabs：概览 / 配置 / 日志 / 版本 / 调用记录。
3. 主体：主从两栏或多个分组卡片。
4. 技术信息：ID、Key、JSON、日志等独立放入等宽面板。

规则：
- 对象名旁可放状态标签，但不要把状态写进标题。
- 配置项分组展示，避免长列表无层级。
- 日志和 JSON 不混入普通正文。

## 4. Form / 配置页

适用：分配线索、维护线索数据、转商机、导出审批、留言回访记录、认证状态修改。

结构：

1. 单列居中，容器宽 `--container-narrow: 720px`。
2. 分组卡片：每组一个 Card，字段标签在上。
3. 底部操作区：取消 / 保存，长表单可吸底。
4. 多步复杂配置使用 Steps / Wizard。

规则：
- 必填字段使用红星 + “必填”双重提示。
- 失焦校验为主，提交时全表兜底。
- 多字段编辑优先右侧抽屉；简单确认用居中弹窗。

## 5. Settings / 设置页

适用：账号、安全、成员、通知、系统配置、业务规则配置。

结构：

1. 左侧二级导航。
2. 右侧设置内容。
3. 每节一个卡片：标题 + 说明 + 控件 + 独立保存。

规则：
- 不同设置项不要共用一个全局保存按钮，除非确实属于同一配置组。
- 危险设置区与普通设置区分离，使用 danger 语义。

## 6. Empty / 引导页

适用：无留言工单、无线索、无审核记录、无知识条目、无权限可见内容。

结构：

1. 居中图标 / 插画。
2. 一句说明：为什么为空。
3. 一个主操作：下一步做什么。
4. 可选帮助链接。

规则：
- 不要只写“暂无数据”。
- 主操作必须明确，例如“新增线索”“创建回访记录”“上传知识”。

## 7. Log / 技术内容页

适用：日志、调试、运行记录、JSON 输出、API 响应。

结构：

1. 页头：标题 + 时间范围 / 级别筛选。
2. 工具栏：搜索、级别筛选、复制、导出。
3. 日志面板：深底、等宽、可滚动。
4. 错误详情：可折叠，避免直接占满页面。

规则：
- debug/info/warn/error 使用统一日志色。
- 长内容必须可复制、可横向滚动或折叠。

## 8. Permission / 成员权限页

适用：成员管理、角色配置、权限矩阵。

结构：

1. 页头：标题 + 邀请 / 新建角色。
2. 成员列表或权限矩阵表格。
3. 角色说明卡片。
4. 危险操作二次确认。

规则：
- 权限变更要提供明确反馈。
- 管理员、拥有者等关键角色使用标签标识。

## 9. Skill Hub / 技能管理页

适用：Skill Hub、Skill 包状态管理、平台 PM / 管理员审批、发布、启停、评估验证。

结构：

1. 页头：标题 + 说明 + 右侧 `创建 Skill` / `刷新` 等操作。
2. 摘要卡：全部、草稿、待审批、已发布、已禁用等状态计数。
3. 筛选栏：搜索 + 状态 + 分类 + 标签 + 重置。
4. 表格：名称、描述、版本、线上版本、状态、分类、标签、更新时间、操作。
5. 行内操作：查看、编辑、测试、提交审核、审批、发布、禁用、启用、删除等按权限/状态显示。
6. 弹窗：详情查看用大弹窗或抽屉；状态变更用确认弹窗；测试用评估验证弹窗。

规则：
- 这是数据管理页，不做卡片瀑布流；默认以表格为主，便于比较状态和版本。
- 状态标签统一浅底 + 实色文字 + 可选小圆点；状态色不得与危险操作混淆。
- 行内操作保持 12px 文字按钮或紧凑描边按钮，不能撑高表格行。
- 高影响操作（发布、禁用、删除、审批、驳回）必须二次确认并说明影响范围。
- 评估验证过程需要明确运行中、通过、失败、警告状态，完成后提供继续操作。

## 10. Local Preview / 本地预览入口

适用：`public/admin/index.html`、`preview.html`、`workbench.html?demo=1`、本地启动脚本页面。

结构：

1. 预览入口页：品牌 mark + 标题 + 简短说明 + 主操作 `直接进入工作台`。
2. Demo 工作台：加载真实 `workbench.html?demo=1`，用 demo mock 拦截接口。
3. 本地服务说明：给出 `start-preview` 启动方式和本机/局域网访问入口。

规则：
- 预览入口只负责进入真实工作台，不复制一份静态假界面。
- Demo 模式必须加载与生产页面一致的 CSS 覆盖层和 JS 模块，避免“预览样式正确、真实页面不一致”。
- 入口页仍遵守 Leaibot token：浅灰画布、白色卡片、蓝色主操作、联想红 mark。
