## SPEC-01：访问入口与账号开通合并

### 目标

- 内部用户首次登录无权限时，直接在无权限错误页内填写基本信息、选择角色、功能权限和数据权限并提交，不再先申请账号，也不跳转权限管理后台。
- 外部登录页不提供自助创建账号入口。
- 外部账号只能由内部关联人创建，并在创建流程内同步选择权限范围。

### 业务规则

1. 无权限页“申请访问权限”是导航入口，不在错误页创建独立申请单。
2. 错误页原地展示“基本信息、权限范围、提交申请”三步流程，预填当前内部 ITCode，不进入权限管理后台。
3. 创建外部账号时，申请人即关联人；关联人字段自动带出且只读。
4. 创建账号流程必须保留权限范围步骤，提交一张包含账号资料和权限范围的申请。

### 不做

- 本阶段不调整最终审批节点顺序，由 SPEC-02 统一处理。
- 不接真实外部账号创建 API。

### 验收

- 对应 `P01-01` 至 `P01-03`。

## SPEC-02：身份化审批链路与审批摘要

### 目标

根据申请人/被申请人的内外部身份和是否本人申请，生成唯一且可解释的审批链。

### 审批矩阵

| 场景 | 审批链 |
| --- | --- |
| 内部用户为自己申请 | 申请人直线经理→全部业务负责人→系统自动生效 |
| 内部用户为其他内部用户申请 | 申请人直线经理→被申请人直线经理→全部业务负责人→系统自动生效 |
| 内部用户为外部用户申请 | 关联人（与申请人一致时省略）→申请人直线经理→全部业务负责人→系统自动生效 |
| 外部用户为自己申请 | 关联人→全部业务负责人→系统自动生效 |
| 外部用户为其他外部用户申请 | 被申请人关联人→全部业务负责人→系统自动生效 |

### 业务规则

1. 外部用户没有直线经理；被申请人为外部用户时，不展示也不生成“被申请人直线经理”。
2. 同一节点的关联人与申请人为同一人时，省略关联人节点。
3. 涉及多个业务负责人时并行等待，全部通过后整单一次性自动生效。
4. 普通权限变更不再生成系统管理员最终审批节点。
5. 系统管理员仅保留启用、禁用等实际操作或管理确认场景。
6. 申请人最终提交页只展示审批流；详细变更摘要放在审批列表/审批详情。

### 验收

- 对应 `P02-01` 至 `P02-05`。

## SPEC-03：复制权限与账号操作提单

### 目标

清楚区分“复制锁定范围”和“本次手工追加范围”，同时取消启禁用场景的手填单号。

### 业务规则

1. 复制当前有效的角色、功能权限、数据权限和用户级例外。
2. 不复制租户、组织归属和账号资料。
3. 复制结果整体只读，不允许增加、删除、局部清除或修改来源。
4. “添加角色”“添加数据权限”仍可独立使用；手工追加的内容可在提交前调整或删除。
5. 最终权限范围为：锁定复制结果＋手工添加角色＋手工添加数据权限。
6. 启用/禁用表单不展示申请单号输入框；提交后系统自动生成单号并用于审批与记录。

### 验收

- 对应 `P03-01` 至 `P03-03`。

## SPEC-04：用户管理统一编辑

### 目标

降低用户列表操作列复杂度，将基本信息、角色和数据权限维护收拢到同一编辑入口。

### 业务规则

1. 用户列表删除独立的“分配数据权限”和“设置角色”操作。
2. “编辑”打开统一用户工作区，保留基本信息、角色、数据权限、历史变更和登录日志页签。
3. “详情”继续以只读模式打开相同工作区，可从详情进入编辑。
4. 启用/禁用作为独立高风险操作保留。

### 验收

- 对应 `P04-01`、`P04-02`。

## SPEC-05：数据源一级目录绑定

### 目标

数据源只绑定到一级目录/大菜单，避免每个子菜单重复维护。

### 业务规则

1. 新增和编辑数据源时，只能选择功能目录树的一级根节点。
2. 数据源保存的 `menu` 和 `group` 统一为一级目录名称。
3. 列表树、详情、筛选和权限引用均以一级目录展示。
4. 既有子菜单 mock 数据在页面初始化时归一到对应一级目录。

### 验收

- 对应 `P05-01`、`P05-02`。
