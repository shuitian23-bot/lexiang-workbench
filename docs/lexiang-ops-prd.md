# 乐享运营看板 PRD

版本：V0.1  
日期：2026-06-04  
范围：联想乐享 AI 工作台 / 乐享运营  
面向对象：业务负责人、运营、数据、研发、测试

## 1. 背景与目标

乐享运营板块用于承载联想乐享的经营看板和专项分析能力。当前页面已有运营总览、Query 分析、质量分析、流量分析、GMV 分析等入口，但存在三类问题：

1. 页面职责不够收敛，深入分析、归因、异常解释等动作不应该继续摊在更多菜单里。
2. 流量分析、GMV 分析中存在真实数据、估算数据、回算数据、示例数据混用，需要明确口径。
3. AI 助手需要从通用聊天变成基于当前看板、当前时间范围、当前阶段目标的数据分析助手。

本 PRD 目标：

- 明确乐享运营菜单信息架构。
- 明确每个页面的业务目标、模块、交互和验收标准。
- 明确核心指标计算逻辑、字段来源和数据真实性。
- 明确 AI 助手的能力边界和输出要求。
- 形成可与业务对齐、对齐后可交给研发正式开发的需求依据。

## 2. 范围

本 PRD 只覆盖左侧一级菜单“乐享运营”下的二级菜单：

## 4. 全局交互要求

### 4.1 时间筛选

运营总览、流量分析、GMV 分析统一支持：

- 最近1天
- 最近7天
- 最近14天
- 最近30天
- 自定义日期范围

交互要求：

- 时间选项平铺展示。
- 点击“自定义”后，在同一行展示开始日期和结束日期，不能错行。
- 自定义日期范围为闭区间，即包含开始日期和结束日期。
- 当前可用数据边界来自数据源最小/最大日期。
- 当前 Excel 静态数据边界为 2026-04-01 至 2026-04-26。
- 最近 N 天按当前数据源最后一天向前取 N 条日数据；当前最近1天为 2026-04-26。

### 4.2 数据真实性标注

所有非原始真实数据必须在标题或指标旁标注。

| 标签 | 含义 | 示例 |
|---|---|---|
| 真实数据 | 来自业务原始数据或业务确认后的接口 | DAU、登录、互动、购买、整体 GMV |
| 非原始·回算 | 使用原始数据加规则分摊或回算 | 分业务 GMV |
| 非原始·估算 | 按权重、模型或规则估算 | 监测媒体 TOP10、Query 场景分布 |
| 示例数据 | 演示用静态数据，不能作为业务决策依据 | 热门商品 TOP5 |
| Mock 数据 | 前端随机生成或模拟数据，正式开发必须替换 | 当前质量分析数据 |

页面原则：

- 真实数据不强制显示标签，但必须可查看口径说明。
- 回算、估算、示例、Mock 必须在标题处显示标签。
- AI 解读必须知道哪些数据是真实、回算、估算、示例或 Mock，不能把估算/示例/Mock 当真实结论。

## 6. 通用计算逻辑

设选期日数据为 `rows`：

- 最近1天：取 `daily` 最后一条。
- 最近7/14/30天：取 `daily` 最后 N 条，若不足 N 条则取全部。
- 自定义：筛选 `start <= rowDate <= end` 的所有日数据。

通用公式：

| 指标 | 公式 |
|---|---|
| 求和 | `sum(rows, field) = Σ row[field]` |
| 均值 | `avg(rows, field) = round(sum(rows, field) / rows.length)` |
| 占比 | `part / total * 100%`，total 为 0 时显示 `-` |
| 首尾变化 | `(last - first) / first * 100%`，first 为 0 时显示 `-` |
| 日均 GMV | `avg(rows, gmv)` |
| 客单价 | `gmv / buy`，buy 为 0 时显示 `-` |

## 7. 页面需求

## 7.1 运营总览

### 页面目标

运营总览是乐享运营默认首页，用于回答：

- 当前选期整体经营表现如何？
- 活跃、互动、购买、GMV 的链路是否健康？
- 不同业务和平台的交易贡献如何？
- 最近趋势有什么变化？
- 如果输入阶段目标，当前差距在哪里、优先动作是什么？

### 页面模块

1. 时间筛选与 AI 解读。
2. 核心指标卡：DAU、WAU、MAU、GMV。
3. 关键经营链路：登录用户、互动用户、购买人数、成交 GMV。
4. 交易指标 · 分业务。
5. 交易指标 · 分平台。
6. 核心趋势速览。
7. Query 场景分布。
8. 热门商品 TOP5。
9. AI 阶段目标分析。

### 指标口径

| 指标 | 计算逻辑 | 数据属性 |
|---|---|---|
| DAU | `avg(rows, dau)` | 真实数据 |
| WAU | `avg(rows, wau)` | 真实数据，需业务确认选期展示均值还是最后一天快照 |
| MAU | `avg(rows, mau)` | 真实数据，需业务确认选期展示均值还是最后一天快照 |
| GMV | `sum(rows, gmv)` | 真实数据 |
| 日均登录 | `avg(rows, login)` | 真实数据 |
| 登录用户 | `sum(rows, login)` | 真实数据 |
| 互动用户 | `sum(rows, inter)` | 真实数据 |
| 购买人数 | `sum(rows, buy)` | 真实数据 |
| 登录/日活 | `sum(login) / (avg(dau) * rows.length)` | 真实数据衍生 |
| 互动/登录 | `sum(inter) / sum(login)` | 真实数据衍生 |
| 购买/互动 | `sum(buy) / sum(inter)` | 真实数据衍生 |
| 成交 GMV | `sum(rows, gmv)` | 真实数据 |
| 日均 GMV | `avg(rows, gmv)` | 真实数据衍生 |
| 官网 GMV | `sum(rows, offGmv)` | 真实数据 |
| 非官网 GMV | `sum(rows, nonGmv)` | 真实数据 |
| 官网购买人数 | `sum(rows, offBuy)` | 真实数据 |
| 非官网购买人数 | `sum(rows, nonBuy)` | 真实数据 |
| 平台 GMV 占比 | `offGmv / (offGmv + nonGmv)`、`nonGmv / (offGmv + nonGmv)` | 真实数据衍生 |
| Query 场景分布 | 按固定权重分摊 `sum(inter)` 或 `sum(login)` | 非原始·估算 |
| 热门商品 TOP5 | 静态示例商品列表 | 示例数据 |

### 分业务 GMV 回算逻辑

当前 Excel 中存在消费、SMB、政企的登录口径 GMV/购买人数，但整体 `daily.gmv` 还包含平台交易回算部分。当前页面使用以下逻辑：

1. 对选期分别求出三类业务登录口径数据：
   - `bizLoginGmv[i] = sum(bizRows[i], gmv)`
   - `bizLoginBuy[i] = sum(bizRows[i], buy)`
2. 计算登录口径合计：
   - `loginGmvTotal = sum(bizLoginGmv)`
   - `loginBuyTotal = sum(bizLoginBuy)`
3. 计算待分摊的平台交易差额：
   - `extraGmv = max(0, sum(daily.gmv) - loginGmvTotal)`
   - `extraBuy = max(0, sum(daily.buy) - loginBuyTotal)`
4. 按三类业务登录口径 GMV/购买人数权重分摊：
   - `bizPlatformGmv[i] = extraGmv * bizLoginGmv[i] / loginGmvTotal`
   - `bizPlatformBuy[i] = extraBuy * bizLoginBuy[i] / loginBuyTotal`
   - 若权重和为 0，则均分。
5. 得到展示用分业务交易：
   - `bizGmv[i] = bizLoginGmv[i] + bizPlatformGmv[i]`
   - `bizBuy[i] = bizLoginBuy[i] + bizPlatformBuy[i]`

该口径必须标注为“非原始·回算”。正式开发前需要业务确认该分摊规则是否可接受，或者提供原始分业务交易字段。

### AI 解读需求

点击“AI 解读”后，AI 必须基于当前选期数据输出：

- 结论摘要。
- 关键趋势：DAU、登录、互动、GMV 的首尾变化、峰值、低点。
- 链路瓶颈：登录/日活、互动/登录、购买/互动。
- 业务贡献：消费、SMB、政企的 GMV 和购买占比。
- 平台结构：官网/非官网 GMV 和购买占比。
- 风险与机会。
- 需要业务补充的数据。

阶段目标输入框：

- 用户可输入如“近30天 GMV 提升10%，互动率不下降”。
- AI 结合阶段目标输出目标差距、关键缺口、优先动作。
- 如果目标无法用当前数据判断，AI 必须指出缺少的数据。

## 7.3 质量分析

### 页面目标

质量分析用于回答：

- AI 回复质量是否稳定？
- 用户负反馈、低满意、异常是否上升？
- 性能是否影响体验？
- 哪些工具、场景、Agent 异常最多？
- 哪些质量问题需要运营、知识库或研发处理？

### 当前状态

当前质量分析数据由前端 `_genMockData()` 随机生成，正式开发必须接入真实质量数据源。页面上需增加“Mock 数据”或“待接入真实数据”标注，直到真实接口上线。

### 页面模块

1. 日期筛选。
2. 原生质量：点踩率、低满意率、点踩 case、低满意度 case。
3. 智能客服质量：点踩率、点踩 case、智能客服总量、转人工率。
4. 性能：首 token avg/p90/p95/p99、分意图首 token、问答类正文首 token、等待时长。
5. 对话质量：平均对话轮数、人均交互次数、多轮对话占比、单轮解决率。
6. 异常：异常占比、MCP 异常、用户中断率、回复空白率、工具失败、场景工具失败、Agent 异常、核心工具异常。
7. 用户评分：OSAT、NPS、净评价值。
8. 低质量样本列表，正式开发新增。
9. 改进跟踪，正式开发新增。

### 指标口径

| 指标 | 计算逻辑 |
|---|---|
| 点踩率 | `thumbdown_count / (active_queries - cs_queries)` |
| 低满意率 | `low_sat_count / survey_samples` |
| 智能客服点踩率 | `cs_thumbdown / cs_queries` |
| 转人工率 | `transfer_sessions / cs_queries`，当前 mock 直接给 `cs_transfer_rate` |
| 首 token avg | 首 token 耗时平均值 |
| 首 token p90/p95/p99 | 首 token 耗时对应分位值 |
| 单次会话平均等待时长 | 会话总等待时长 / 会话数 |
| 单次回答平均等待时长 | 回答等待总时长 / 回答数，需区分 `<=300字` 与 `>300字` |
| 平均对话轮数 | `sum(session_turns) / session_count` |
| 人均交互次数 | `interaction_count / user_count` |
| 多轮对话占比 | `turns >= 2 的会话数 / 总会话数` |
| 单轮解决率 | `turns = 1 且达成解决标准的会话数 / 总会话数`，当前 mock 使用单轮会话占比 |
| 异常占比 | `error_cases / total_cases` |
| MCP 异常次数 | MCP 调用异常计数 |
| 用户中断率 | `interrupted_interactions / total_interactions` |
| 回复空白率 | `empty_responses / total_responses` |
| OSAT | 业务满意度评分，需确认量表 |
| NPS | 推荐者占比 - 贬损者占比 |
| 净评价值 | `(like_count - dislike_count) / (like_count + dislike_count)` |

| 月登录均值 | `avg(rows, loginM)` | 真实数据衍生，需确认字段定义 |
| 端口访问 | `sum(traffic[port].uv)` | 真实数据 |
| 端口登录 | `sum(traffic[port].login)` | 真实数据 |
| 端口互动 | `sum(traffic[port].inter)` | 真实数据 |
| 端口购买 | `sum(traffic[port].buy)` | 真实数据 |
| 端口 GMV | `sum(traffic[port].gmv)` | 真实数据 |
| 端口占比 | 当前选中指标下，`port.value / sum(port.value)` | 真实数据衍生 |
| 分业务登录 | `sum(consumer/smb/gov.login)` | 真实数据 |
| 分业务互动 | `sum(consumer/smb/gov.inter)` | 真实数据 |

### 监测媒体估算口径

当前页面没有原始媒体来源数据，使用固定权重把端口总量分摊到 TOP10 媒体。

| 媒体 | 权重 |
|---|---:|
| 百度搜索 | 22 |
| 微信生态 | 18 |
| 抖音 | 14 |
| 小红书 | 11 |
| 今日头条 | 9 |
| B站 | 8 |
| 知乎 | 6 |
| 微博 | 5 |
| 腾讯广告 | 4 |
| 自然外链 | 3 |

计算逻辑：

- 先汇总端口总量：`totals[field] = sum(port[field])`
- 对 `uv/login/inter/buy/gmv` 分别按媒体权重分摊。
- 当前选中指标为访问/登录/互动时，对应使用 `uv/login/inter` 排序和计算占比。

该模块必须标注“非原始·估算”。正式开发建议接入真实媒体来源字段，例如 `utm_source/referrer/channel/media_id`。

### AI 解读需求

AI 解读需要基于当前选期和当前指标维度输出：

- 活跃趋势是否上升/下降。
- 登录、互动转化是否有瓶颈。
- TOP 媒体贡献排序，并明确媒体数据为估算。
- 端口结构中 APP/WAP/PC/小程序等贡献与异常。
- 分业务登录/互动结构。
- 需要补充的数据，如真实来源、用户分层、异常流量识别。

## 7.5 GMV 分析

### 页面目标

GMV 分析用于回答：

- 当前选期 GMV 与购买人数表现如何？
- GMV 主要来自消费、SMB 还是政企？
- 官网与非官网结构是否健康？
- GMV 波动来自业务、平台还是单日异常？

### 页面模块

1. 时间筛选与 AI 解读。
2. GMV 核心指标：整体 GMV、消费 GMV、SMB GMV、政企 GMV。
3. GMV 趋势，可切换整体/消费/SMB/政企。
4. 分业务 GMV 占比。
5. 业务贡献明细。
6. 分平台 GMV：官网 vs 非官网。
7. 平台趋势。

### 指标口径

| 指标 | 计算逻辑 | 数据属性 |
|---|---|---|
| 整体 GMV | `sum(rows, gmv)` | 真实数据 |
| 购买人数 | `sum(rows, buy)` | 真实数据 |
| 客单价 | `sum(gmv) / sum(buy)` | 真实数据衍生 |
| 日均 GMV | `avg(rows, gmv)` | 真实数据衍生 |
| 消费业务 GMV | 见分业务 GMV 回算逻辑 | 非原始·回算 |
| SMB 业务 GMV | 见分业务 GMV 回算逻辑 | 非原始·回算 |
| 政企业务 GMV | 见分业务 GMV 回算逻辑 | 非原始·回算 |
| 分业务占比 | `bizGmv / totalGmv` | 非原始·回算 |
| 官网 GMV | `sum(rows, offGmv)` | 真实数据 |
| 非官网 GMV | `sum(rows, nonGmv)` | 真实数据 |
| 官网/非官网占比 | `offGmv/nonGmv / (offGmv + nonGmv)` | 真实数据衍生 |

### GMV 归因待确认

正式开发前，业务需要确认：

- GMV 是否只统计支付成功订单。
- 是否扣除退款、取消订单。
- 是否含税费、运费、优惠券、满减。
- 官网/非官网的定义。
- 分业务 GMV 是否可以继续使用当前回算规则，还是必须提供原始分业务订单 GMV。
- AI 贡献 GMV 是否需要单独统计，若需要，归因规则是直接推荐、辅助转化还是多触点归因。

### AI 解读需求

AI 解读需要基于当前选期输出：

- 整体 GMV、购买人数、客单价变化。
- 高峰日/低谷日及可能原因。
- 分业务贡献差异，并声明分业务为回算口径。
- 官网/非官网结构与风险。
- 若输入阶段目标，分析缺口和优先动作。
- 明确缺少哪些数据才能做更准确归因。

## 8. AI 助手整体需求

### 8.1 入口

- 运营总览：顶部“AI 解读”、关键经营链路“问 AI”、右侧 AI 助手快捷问题、阶段目标分析。
- 流量分析：顶部“AI 解读”、快捷问题如入口贡献、媒体 TOP10、登录转化、端口结构。
- GMV 分析：顶部“AI 解读”、快捷问题如 GMV 解读、业务贡献、平台结构、目标缺口。
- 质量分析：建议新增质量解读、异常归因、低质量样本归因。
- Query 分析：本轮不新增能力。

### 8.2 上下文要求

AI 每次分析必须带入：

- 当前页面。
- 当前时间范围。
- 当前筛选指标。
- 当前阶段目标。
- 当前页面核心指标、趋势、明细。
- 数据真实性标签。

AI 回答格式：

1. 先给结论。
2. 再列关键证据。
3. 说明可能原因。
4. 给出优先动作。
5. 明确缺失数据与需要业务补充的口径。

AI 禁止：

- 编造页面未提供的数据。
- 把估算/示例/Mock 数据当真实数据。
- 忽略用户选择的时间范围。
- 用通用建议替代当前看板分析。
