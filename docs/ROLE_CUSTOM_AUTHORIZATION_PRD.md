# 角色管理—自定义授权产品需求文档（PRD）

版本：v1.0  
更新日期：2026-09-04  
文档状态：基于已完成 POC 的需求确认稿  
适用产品：联想乐享 AI 工作台权限管理系统

## 1. 文档目的

本文定义“角色管理 → 新增/编辑角色 → 数据权限 → 自定义授权”的产品需求，作为产品评审、交互设计、前后端开发、测试验收和后续生产化的统一依据。

本文只描述角色级自定义数据授权。用户级自定义授权复用相同的数据集目录、配置组件和校验规则，但其审批与生效流程不在本文范围内。

## 2. 背景与问题

普通数据授权只能控制用户是否可以访问某个完整数据集，无法满足以下场景：

- 同一个数据集只允许某个角色查看指定区域、业务线或渠道的数据。
- 同一个数据集只允许某个角色查看部分字段，例如允许查看商品名称和库存，但不允许查看价格。
- 多个结构相近的数据集需要配置相同权限，逐表重复操作成本高。
- 批量配置后，个别数据集仍需要保留差异化权限。
- 一个用户拥有多个角色时，不同角色对同一数据集的规则可能互相冲突，导致最终权限无法解释。

因此需要提供以“数据集 + 行权限 + 列权限”为核心的角色自定义授权能力，并保证配置结果可理解、可校验、可回显和可审计。

## 3. 产品目标

### 3.1 核心目标

1. 允许有权限的管理员为角色配置二维数据集的行、列访问范围。
2. 支持一次维护全部数据集，避免新增、编辑、删除规则分散在多个入口。
3. 支持多数据集批量配置，并允许批量后继续调整单张数据集。
4. 固定并清楚解释授权计算方式，避免管理员误解最终可访问范围。
5. 在保存角色前识别多角色权限冲突，避免把不可解释的权限组合带给用户。
6. 为生产后端保留稳定的数据集、维度、维度值和列字段标识。

### 3.2 成功标准

- 管理员能够在一次弹层会话中完成数据集新增、修改和移除。
- 批量配置结果能够完整回显到每一张数据集，单表修改不影响其他数据集。
- 不完整或冲突的权限规则无法保存。
- 取消、遮罩关闭或按 Esc 不会污染已保存权限。
- 查看态与编辑态对同一规则的展示结果一致。

## 4. 用户与权限

| 用户角色 | 能力 |
| --- | --- |
| 系统管理员 | 新增、查看和编辑角色，可配置角色自定义授权 |
| 角色管理员 | 在其被授权的角色组范围内查看、编辑角色及自定义授权 |
| 普通申请人 | 在角色详情中只读查看角色已经包含的自定义授权，不可修改 |
| 普通用户 | 按最终生效的角色权限访问数据，不进入角色配置页面 |

生产环境必须由后端校验操作者是否有权管理目标角色及角色组，不能仅依赖前端隐藏按钮。

## 5. 范围

### 5.1 本期范围

- 新增角色和编辑角色中的自定义授权。
- 数据集搜索、标签筛选、选择和移除。
- 数据集标签维护。
- 单张数据集的行权限、列权限配置。
- 多张数据集的交集批量配置。
- 批量配置后继续修改单张数据集。
- 授权结果预览、完整性校验和角色冲突校验。
- 查看态只读回显。
- 历史规则归一化和变更识别。

### 5.2 非本期范围

- 自定义 SQL、自由表达式或脚本授权。
- 行列规则的 OR/AND 自由切换。
- 排除模式、反选规则或黑名单规则。
- 数据脱敏、字段加密和导出水印策略。
- 用户级自定义授权的审批链路。
- 真实数据源鉴权执行引擎和数据库侧策略下发。
- 角色删除、启停及角色成员维护流程。

## 6. 核心概念

| 概念 | 定义 |
| --- | --- |
| 数据集 | 可以被独立授权的数据对象，具有稳定 `tableId`、名称、说明和标签 |
| 行权限 | 决定角色可以访问哪些业务范围的数据，按区域、业务线、渠道等维度组织 |
| 列权限 | 决定角色可以查看数据集中的哪些字段 |
| 自定义授权规则 | 某个角色针对一张数据集保存的一组行权限和列权限 |
| 普通授权 | 对完整数据集进行整体授权，不配置行列范围 |
| 批量配置 | 将所有已选数据集共同支持的行列字段一次应用到全部目标数据集 |
| 角色冲突 | 同一用户的多个角色对同一数据集配置了不一致的自定义授权规则 |

## 7. 总体业务规则

1. 一个角色的普通数据授权和自定义授权互斥，不能同时存在。
2. 自定义授权以数据集为单位；同一角色对同一数据集最多保存一条归一化规则。
3. 每条规则必须至少包含一个行权限值和一个列字段。
4. 行权限和列权限的运算关系固定为“与（AND）”：只有行范围和列字段同时命中时，对应数据单元格才可访问。
5. 页面不提供 OR、排除或反选入口。
6. 数据集、行维度、维度值和列字段必须使用稳定 ID 保存，中文名称只用于展示。
7. 排序变化、重复 ID 或临时规则 ID 变化不构成权限变更；真实的数据集、行值或列字段增删构成权限变更。
8. 编辑角色规则后，如果会导致该角色已分配用户出现多角色冲突，则阻止保存角色。
9. 角色保存成功后，后续权限申请和角色详情使用最新角色权限范围；生产环境中角色权限对既有成员的生效时点须采用统一策略并写入审计日志。

## 8. 用户流程

### 8.1 进入自定义授权

1. 管理员进入“角色管理”。
2. 点击“新增角色”或选择一个角色进入“编辑”。
3. 切换到“数据权限”。
4. 选择“自定义授权”。
5. 点击统一主操作“编辑”，打开“编辑自定义授权数据集”弹层。

若角色已有普通数据授权：

- “自定义授权”不可直接使用。
- 页面提示“当前已有普通授权，需取消全部普通授权后才能使用自定义授权”。

若角色已有自定义授权：

- “普通授权”不可直接使用。
- 页面提示“当前已有自定义授权，需删除全部自定义授权后才能使用普通授权”。

### 8.2 维护数据集

1. 弹层左侧展示全部可授权数据集，已添加和未添加数据集同时可见。
2. 已有规则完整回显；未添加数据集默认未勾选。
3. 勾选数据集复选框表示将其加入本次授权，默认全选该表全部行值和列字段。
4. 取消复选框表示从本次完整草稿中移除该数据集。
5. 点击数据集名称只切换右侧详情，不应隐式勾选或取消数据集。
6. “全选当前结果”只选择当前筛选可见的数据集；“清空”取消本次草稿中的全部数据集。

### 8.3 逐表配置

1. 右侧默认进入“逐表配置”。
2. 行权限按业务维度分组展示，每个维度可多选具体值，并提供分组“全选/清空”。
3. 列权限独立展示可授权字段，并提供“全选/清空”。
4. 页面实时展示已选数量和授权结果矩阵。
5. 未添加数据集也可先查看和操作行列字段；首次选中任一行值、列字段或执行有效“全选”时，系统自动勾选该数据集并保留当前选择。
6. 对未添加数据集执行空状态“清空”不得自动添加该数据集。
7. 数据集自动添加后，即使用户清空全部行列权限，也不自动移除数据集；用户需通过左侧复选框明确取消。
8. 已完成批量配置的数据集仍可进入逐表配置；单表最新修改只覆盖该表，不影响其他数据集。

### 8.4 批量配置

1. 至少选择两张数据集后，“批量配置”入口可用。
2. 批量行权限只展示所有已选数据集共同拥有的维度和值交集。
3. 批量列权限只展示所有已选数据集共同拥有的列字段交集。
4. 字段相同必须以稳定 ID 判断，不能只根据中文名称判断。
5. 行权限与列权限均至少选择一项后，才可点击“应用到已选数据集”。
6. 应用成功后，同一批量规则一次写入所有已选数据集的草稿，并可在逐表配置中分别回显。
7. 任一目标数据集不支持所选字段时，本次批量应用整体失败，不允许只更新部分数据集。
8. 已选数据集集合变化时，立即重新计算交集，移除已经不属于新交集的选项，并使上一次“应用完成”状态失效。
9. 任一权限轴没有共同字段时，展示明确空状态并禁止应用和最终保存。

### 8.5 保存与取消

弹层采用完整草稿模式：

- 打开弹层时，以角色当前已保存规则复制一份草稿。
- 勾选、取消、逐表配置、批量配置仅修改草稿。
- 点击“保存自定义授权”后，以草稿一次性替换角色原有全部自定义规则。
- 点击“取消”、遮罩或按 Esc 时丢弃全部未保存草稿。
- 关闭后焦点返回原“编辑”按钮。
- 数据集标签存在未保存草稿时，应先提示保存或取消标签修改，不能静默丢失。

保存弹层只更新角色编辑表单中的权限草稿；管理员仍需点击角色编辑页底部“保存”，角色配置才最终保存。

## 9. 数据集搜索与标签

### 9.1 统一筛选控件

- 搜索输入框与标签筛选按钮位于同一个控件外框内。
- 关键词可匹配数据集名称、说明或标签。
- 关键词与标签两个筛选条件按 AND 组合。
- 同时选择多个标签时，标签之间按 OR 计算，命中任一标签即可。
- 标签按钮显示已选数量，并通过提示展示完整已选标签。
- 标签下拉支持逐项取消和一键清空；选项过多时仅下拉内部滚动。
- Esc 或点击外部只关闭标签下拉，不清除当前筛选条件。
- 没有标签或没有匹配数据集时展示对应空状态。

### 9.2 标签维护

- 角色新增/编辑状态允许维护数据集标签；只读状态不显示“编辑标签”。
- 每个数据集最多 5 个标签。
- 每个标签最多 12 个字符。
- 自动移除首尾空格，标签名称不允许重复。
- 可复用已有标签，也可创建新标签。
- 只有点击“保存标签”才生效；取消或首次按 Esc 放弃标签草稿。
- 标签属于数据集目录元数据，不属于角色授权规则。
- 修改标签不得改变数据集是否选中、行权限或列权限。
- 未被任何数据集使用的标签不再出现在筛选选项中。

POC 使用浏览器本地存储保存标签；生产环境必须改为后端数据集目录接口，并记录修改人、修改时间和变更前后值。

## 10. 校验与异常处理

| 场景 | 系统行为 |
| --- | --- |
| 数据集缺少行权限 | 指明数据集名称和“缺少行权限”，阻止保存 |
| 数据集缺少列权限 | 指明数据集名称和“缺少列权限”，阻止保存 |
| 普通授权与自定义授权同时存在 | 提示只能选择一种，阻止保存角色 |
| 批量配置缺少任一权限轴 | 禁用应用按钮，并说明需要至少选择一个行权限和一个列权限 |
| 批量字段并非所有数据集共有 | 展示不匹配数量、数据集名称和缺失字段，整体阻止应用 |
| 标签超出数量或长度 | 在标签编辑区就近提示，不保存标签 |
| 标签重复 | 提示标签名称不能重复 |
| 标签存在未保存草稿 | 阻止切换数据集、进入批量配置或提交，并提示先保存或取消 |
| 数据集目录已删除字段 | 保存前过滤无效 ID；若导致规则不完整，则阻止保存并定位数据集 |
| 角色修改导致既有用户角色冲突 | 展示受影响用户和冲突原因，阻止保存角色 |
| 保存接口失败 | 保留当前草稿，展示可重试错误，不得显示成功或关闭弹层 |
| 重复提交 | 保存按钮进入处理中状态并禁止再次点击 |

## 11. 多角色冲突规则

### 11.1 允许保存

- 两个角色没有配置相同数据集。
- 两个角色配置了相同数据集，且归一化后的行权限集合和列权限集合完全一致。
- 规则仅存在顺序、重复项或临时 ID 差异，实际权限范围一致。

### 11.2 阻止保存或分配

两个角色包含同一数据集，但任一行维度值或列字段不同，即判定为冲突。

冲突提示至少包含：

- 冲突数据集名称。
- 冲突角色名称。
- 每个角色的行权限摘要。
- 每个角色的列权限摘要。
- 受影响用户数量及代表性用户。
- 可恢复路径：取消其中一个角色，或先统一相关角色的自定义授权。

用户直接配置的用户级自定义授权不参与“角色之间”的冲突判断，也不能掩盖角色冲突。

## 12. 数据模型

### 12.1 数据集目录

```json
{
  "tableId": "product-operations-table",
  "name": "商品运营二维表",
  "description": "按业务范围与商品字段控制商品运营数据的访问权限。",
  "tags": ["商品运营", "经营分析"],
  "rowDimensions": [
    {
      "dimensionId": "region",
      "name": "区域",
      "values": [{ "valueId": "nationwide", "name": "全国" }]
    }
  ],
  "columnFields": [{ "fieldId": "record-status", "name": "记录状态" }]
}
```

### 12.2 角色自定义授权规则

```json
{
  "roleId": "product-op",
  "rules": [
    {
      "tableId": "product-operations-table",
      "logic": "AND",
      "rowSelections": [
        {
          "dimensionId": "region",
          "valueIds": ["nationwide"]
        }
      ],
      "columnFieldIds": ["product-name", "stock", "record-status"]
    }
  ],
  "version": 7
}
```

POC 当前内部模型兼容扁平 `rowFieldIds`；生产接口应同时携带 `dimensionId`，避免不同维度出现同名或重复值时产生歧义。

## 13. 生产接口建议

| 接口 | 用途 |
| --- | --- |
| `GET /permission-datasets` | 获取数据集、标签、行维度和值、列字段及可用状态 |
| `PUT /permission-datasets/{tableId}/tags` | 保存数据集标签 |
| `GET /roles/{roleId}/custom-data-permissions` | 获取角色当前自定义授权和版本号 |
| `PUT /roles/{roleId}/custom-data-permissions` | 原子替换角色全部自定义授权规则 |
| `POST /roles/custom-data-permissions/validate` | 保存前校验规则完整性、字段有效性和角色冲突 |
| `GET /roles/{roleId}/permission-impact` | 获取角色变更影响用户与冲突明细 |

接口要求：

- 保存采用完整替换语义，并在事务内完成规则校验、写入和审计记录。
- 请求携带版本号或 ETag，发现并发修改时返回冲突，不覆盖他人新配置。
- 服务端重新校验数据集、维度值和列字段是否存在且可授权。
- 服务端重新执行普通/自定义互斥和多角色冲突校验。
- 返回明确错误码、数据集 ID、字段 ID 和用户可读信息，前端可定位到具体问题。

## 14. 审计与安全要求

- 记录操作者、角色、操作时间、变更原因和客户端请求标识。
- 记录新增、删除和修改的数据集，以及变更前后的行列权限集合。
- 记录标签变更，但标签变更与权限规则变更分开审计。
- 不在前端或日志中输出超出操作者权限范围的真实业务数据。
- 后端鉴权必须覆盖查看、编辑、标签维护、影响分析和保存接口。
- 角色权限变化应支持追溯到具体版本，必要时能够按审计记录恢复。

## 15. 非功能要求

- 1440×900 和 1280×800 下弹层底部操作始终可达。
- 左侧数据集列表、右侧配置区、维度值列表和结果矩阵各自承担明确滚动，不产生页面级横向滚动。
- 数据集目录首次加载展示加载状态；加载失败提供重试入口。
- 搜索和本地字段选择应即时响应；生产目录较大时搜索响应建议不超过 500ms。
- 保存操作必须具备处理中、成功和失败状态，不能重复提交或静默失败。
- 支持键盘 Tab、Esc、焦点进入搜索框和关闭后焦点恢复。

## 16. 验收标准

| ID | 场景 | 验收结果 |
| --- | --- | --- |
| RA-01 | 进入角色数据权限 | 可在普通授权和自定义授权之间选择；已有另一种授权时禁止直接切换并给出清理提示 |
| RA-02 | 打开自定义授权编辑 | 已添加与未添加数据集同时展示，已有规则完整回显 |
| RA-03 | 搜索与标签组合筛选 | 关键词和标签按 AND 组合，多标签按 OR 命中，筛选结果与数量准确 |
| RA-04 | 全选当前结果 | 只选中当前可见数据集，隐藏数据集不受影响 |
| RA-05 | 勾选新数据集 | 默认选中全部行值和列字段，并显示完整授权预览 |
| RA-06 | 点击未选数据集名称 | 只切换详情；首次选择行或列权限时自动加入该数据集 |
| RA-07 | 单表配置 | 行权限按维度分组，行列均支持全选和清空，矩阵实时更新 |
| RA-08 | 批量配置 | 仅展示所有已选数据集共同字段，应用后全部目标表正确回显 |
| RA-09 | 批量后调整单表 | 单表结果覆盖该表批量结果，其他数据集保持不变 |
| RA-10 | 改变批量目标集合 | 立即重算交集，清理失效选择并撤销上次批量完成状态 |
| RA-11 | 不完整规则 | 缺少行或列权限时定位到具体数据集并阻止保存 |
| RA-12 | 取消完整草稿 | 取消、遮罩和 Esc 均不改变外层已保存权限 |
| RA-13 | 保存完整草稿 | 新增、修改和删除一次性完整替换外层权限，不重复追加旧规则 |
| RA-14 | 标签维护 | 数量、长度、重复校验有效；保存标签不改变任何权限选择 |
| RA-15 | 历史规则 | OR、空逻辑和非法逻辑统一按 AND 展示和保存 |
| RA-16 | 相同角色规则 | 同一用户的两个角色规则完全一致时允许分配 |
| RA-17 | 冲突角色规则 | 同一数据集行列范围不一致时阻止角色保存或用户角色分配，并展示明细 |
| RA-18 | 查看态 | 完整只读回显数据集、行列权限、标签和授权结果，不展示编辑入口 |
| RA-19 | 并发保存 | 版本不一致时阻止覆盖并提示刷新后重新编辑 |
| RA-20 | 浏览器与布局 | 目标视口无溢出、遮挡或新增控制台错误，键盘和焦点行为正确 |

- 数据集搜索、标签多选筛选和标签维护。

## 18. 待产品确认项

1. 角色自定义授权修改后，对已分配用户是立即生效，还是进入审批后统一生效。建议：高敏感角色走审批，普通角色由授权管理员直接保存并立即生效。
2. 生产环境中数据集标签由角色管理员维护，还是仅允许数据源管理员维护。建议：标签属于目录元数据，由数据源管理员维护；角色管理员只使用标签筛选。
3. 发生既有用户角色冲突时，是否提供批量调整受影响用户的后续入口。建议：本期先阻止保存并提供影响清单，批量修复作为后续能力。
4. 是否允许“无行限制但限制列”或“限制行但全部列”的快捷语义。建议：本期仍要求两轴至少一项，并用全选表达“不限制”。
5. 角色权限变更是否需要填写变更原因。建议：生产环境必填，用于审计和审批说明。
