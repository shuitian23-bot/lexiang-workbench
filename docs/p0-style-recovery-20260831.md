# Member stylesheet recovery across five entrypoints

Baseline bef73abe. Scope: member entry in home/shop-chat/b-chat/biz-chat/brand. Existing code only inserts CSS while loading JS, never waits for CSS and leaves failed links in place. An already registered component bypasses CSS entirely.

Contract: move existing unchanged CSS href expression to a private stylesheet loader. Start CSS and JS together using Promise.all; mount only after both succeed. Reuse loaded link.sheet and share pending stylesheet promise. Error or 8000ms timeout removes failed link/listeners and clears pending promise. Success clears listeners/timer and pending promise; loaded link remains reusable, removed link can be recreated. Existing JS promise lifecycle and cached service remain unchanged. Existing member markup, error message, bridge, mount parameters and active-tab guards are retained. Brand's older CSS query and home preload URL expression stay unchanged.

No visual redesign, design tokens or component CSS changes. No automatic retry loop/new retry button. Retry through re-entry. Loaded CSS is not removed when JS fails. Script already loaded is not downloaded again when CSS retry succeeds. Underlying browser transport cancellation is not guaranteed; late events have detached listeners. Stylesheet parsing/content correctness beyond browser load/sheet is not validated. Existing error UI is reused; no promise of preserving an already displayed view after a reload failure.

Verification: 30 actual-function synthetic DOM/timer cases per runtime, 150/150 candidates pass; baseline 23/30 each. Includes existing 22 script recovery regressions and eight CSS cases: failed CSS blocks mount and retries, cached component still requires CSS, timeout/retry, concurrent reuse, loaded reuse, late events, script failure retains CSS, removed successful link reloads.
