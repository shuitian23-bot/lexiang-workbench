# AI 助手任务清单：线上合并说明

按用户最新要求，授权以本次 Skill 执行为单位。输入“批量授权演示”可生成包含查询、汇总和导出的一个 Skill 执行示例；只需点击“授权”即可继续全部已列明步骤，点击“拒绝”则拒绝整次执行，不再逐项选择。状态在同一任务卡内更新。卡片明确显示使用示例数据，不执行真实查询、导出或修改。

## 已实现

- `AgentTaskCard.vue` 展示一个 Skill 执行、一句范围与影响摘要，以及“授权”和“拒绝”两个按钮；步骤与技术详情默认折叠，单项不重复标题。
- `aiTaskAuthorization.ts` 校验任务、会话、请求 ID、版本和有效期。整次授权携带 `scope: skill-execution` 及全部当前待授权请求的 ID/版本快照；缺项或新增项都会原子拒绝，不能自动放行未确认范围。旧版无 scope 决策仍按原有限分组规则处理。批准与执行完成分开，重复或无效请求不产生新执行。
- `ai.ts` 精确关联待授权的本地查询上下文，修复点击早期卡片却处理最新请求的问题；会话切换或历史恢复会使未结束请求失效。批量队列每项开始前和结果回填前均核对原批准版本，变化后的范围不能沿用旧批准。
- `AgentConversationStates.vue` 把过程默认压缩成概览，按需展开明细；旧授权历史为只读，不恢复执行权限。

## 尚未接入的真实执行

当前仓库的 `/api/harness/chat` 接口返回对话内容，但没有与此任务清单对应的暂停、批准、批量恢复协议。现有 `/api/harness/invoke` 会立即调用工具，不能作为用户授权接口使用。因此本次不调用该接口，也不改变服务端权限或审批规则。

浏览器读取 `aiwork.lenovo.com.cn` 超时；现有发布配置仅能确认 `new.leaibot.cn` 和 `leaibot.cn`，尚未确认 aiwork 与此仓库的对应关系。当前改动不能作为 aiwork 已部署、真实工具已批量执行的证明。

## 线上执行端需提供的约定

下列是对接要求，不是已实现的接口：

| 对象 | 必须包含与校验的内容 |
| --- | --- |
| 任务快照 | 服务端任务 ID、会话归属、当前操作者、业务名称、有效期、环境及请求清单 |
| 待授权请求 | 不变请求 ID、版本、业务动作、精确数据/字段/时间范围摘要、操作类别、影响、审批要求、本次 Skill 执行归属 |
| 用户决策 | 本次 Skill 全部待授权请求的 ID 与版本、同一任务与会话、批准或拒绝、一次性幂等标识；不能用“允许全部后续命令”代替集合 |
| 授权结果 | 服务端重新检查当前身份、角色、范围、审批及请求版本，逐项返回接受或拒绝原因；前端提交不代表批准成功 |
| 执行事件 | 任务/请求/版本、单调事件序号、已授权/执行中/成功/失败状态与业务结果；旧事件、重复事件不得触发重复执行 |
| 重试与变更 | 同范围重试由执行端核验有效授权和幂等键；参数、字段、环境或操作变化必须生成新版本并重新确认 |

当前 Skill 已明确列出的步骤统一授权，不再按读取或导出拆出额外选择。执行端仍需检查每项操作的原有业务权限与审批，界面的一次授权不替代这些要求，也不扩大到其他 Skill、会话或新数据范围。

当前类型限定 `mode: 'preview'`。接入真实执行时应新增经过验证的服务端事件适配器和明确模式，移除本地模拟延时路径；不得仅删除示例提示或把模型文字解析成授权/执行成功。

## 合并验收

先确认 aiwork 的实际源码仓库、分支及发布位置，再选择性合并上述模块；保留其登录态、权限检查和真实执行协议。至少验证多请求错位、整次执行集合完整性、版本变化、过期、重复点击、并发事件、失败与部分成功、刷新恢复，以及服务端拒绝后的界面状态。本次本地测试不替代这项线上集成验收。

权限管理、首登业务负责人、场景技能包创建编辑和四步审批流程均不属于本次修改范围。
