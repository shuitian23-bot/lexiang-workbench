# P0 five-channel exploratory performance baseline and stale preload removal

Baseline f1f6f8b8, 2026-08-31. Five channels, three sequential visits each, 1440x900 visible viewport, 10-second observation windows. Local static copy with no-store responses and in-memory synthetic storage. API calls return local 503; no live order/payment requests. Fonts may use the existing public leaibot.cn URL/cache. Browser process/code/font caches were not reset; first observed and repeat samples are separate, not true cold/warm cache experiments.

Measurement: temporary local-only script marks record synchronous external-script entry execution (including synchronous calls/layout they trigger), excluding download, parse/compile before the first mark and later async callbacks. Native paint/LCP/longtask observers provide initial-display signals. The probe adds overhead and a results overlay only after sampling. No probe is installed in production. This is not a complete real-user production performance profile or CPU attribution.

All 15 samples reported no long tasks >=50ms in the observation windows. This does not prove later interactions are free of long tasks. The static/API-error environment may skip real data work. Initial script work was mainly channel runtime and portal.js. Full APIs, real network throttling, user journey interaction latency and production LCP remain unmeasured.

Concrete release: remove exactly one obsolete app.product-detail-actions-v53.min.js script preload tag from root index.html. The actual home runtime is home.ref-sync-v140.js. Source scan found the old filename only in the root and legacy flat HTML preload tags, not executable script references. Candidate still executes the same ordered 31 scripts, with no captured JS errors or broken images; no request for the stale preload. Keep the old file and legacy HTML intact. Member/store preloads remain because later feature use is not ruled out.

Production gzip GET measured this resource at 174123 body bytes (583536 uncompressed); removing the preload avoids that request/body when it would otherwise be fetched uncached. Not a per-visit guarantee or a claimed page-load speed percentage.

Only index.html changes in the served site. No CSS/JS contents, backend, nginx or user data change. Backup and scoped Git merge required; rollback restores only the removed preload via Git. Baseline JSON and served-resource proof are retained alongside this report.
