# 场景技能包外部创建入口设计

## 目标

在账号工作区中提供“创建场景技能包”的一级快捷入口，让有权限的创建者不必先进入 Skill Hub 的场景技能包管理页，再点击创建。

## 当前状态

- 账号工作区已有“创建 Skill”“Skill Hub”“权限管理”“调整日志”四个入口。
- 场景技能包可从 `Skill Hub → 场景技能包 → 创建场景技能包` 进入。
- 创建页面已经支持直达地址 `/agent/skills?tab=packages&mode=create`，但账号工作区没有暴露该入口。

## 已确认方案

采用独立快捷卡片，不合并或替换现有入口。

### 信息结构

- 第一排为两个创建入口：
  - `创建 Skill`
  - `创建场景技能包`
- 第二排为三个管理入口：
  - `Skill Hub`
  - `权限管理`
  - `调整日志`

宽屏下，两个创建卡片等宽占据第一排，三个管理卡片等宽占据第二排。右侧 Agent 展开或可用宽度不足时，卡片按两列重排；窄屏改为单列，并保证弹层可在视口内滚动。

### 新卡片文案

- 标题：`创建场景技能包`
- 描述：`按业务场景组合、串联已发布 Skill，并完成权限与版本评估。`
- 图标：沿用账号工作区现有图标容器，使用 `◎＋` 表达“从 Skill Hub 组合创建”。

### 交互

点击新卡片后：

1. 关闭账号工作区弹层。
2. 复用 `agent.skills` 静态页签，不新增页面或菜单项。
3. 直接进入 `/agent/skills?tab=packages&mode=create`。
4. 创建页继续使用现有场景定义、Skill 选择、链路配置、权限版本评估和审批发布流程。

现有“创建 Skill”继续进入 `/agent/skill-create`；现有“Skill Hub”继续进入默认管理页，Skill Hub 内部的“创建场景技能包”按钮继续保留。

## 权限与边界

- 快捷入口只缩短导航路径，不改变或绕过权限规则。
- 当前 POC 管理员账号可看到并进入该入口。
- 创建及发布仍由既有规则校验跨菜单编排权限、Skill 引用权限、责任人、固定版本和自动门禁。
- 不修改场景技能包数据结构、运行时权限模型、Skill Hub 审批逻辑或已有场景技能包记录。
- 本轮只更新 `new`，不合并正式环境，不推断 GitLab 上传授权。

## 异常处理

- 新入口复用已注册路由，不新增接口请求或加载状态。
- 如果进入创建页后权限或自动门禁不满足，继续由现有创建流程展示阻断原因；快捷入口本身不伪造可发布状态。
- 页面路由和静态页签均沿用现有 Skill Hub 导航机制，避免出现独立入口与管理状态不一致。

## 实现范围

- 在 `SidebarFooter` 增加独立卡片及事件。
- 在 `WorkbenchSidebar` 增加直达创建流程的导航处理。
- 仅调整账号工作区卡片布局和响应式样式。
- 增加一条独立的 POC 调整记录；发布时只记录 `new` 状态。

## 验收标准

- 账号工作区可见“创建场景技能包”卡片，且与“创建 Skill”并列为创建入口。
- 点击后弹层关闭，并直接显示场景技能包创建流程。
- URL 为 `/agent/skills?tab=packages&mode=create`，活动静态页签为 `agent.skills`。
- 返回或取消后仍回到 Skill Hub 的场景技能包页签。
- 原四个入口行为不回退。
- 桌面、右侧 Agent 展开和窄屏布局无横向溢出；键盘焦点和按钮语义可用。
- 场景技能包测试、产品契约测试、全量 Node 测试、代码检查、类型检查、构建和页面冒烟均通过。
- 发布后 `new` 入口与资源可回读，受保护的 `admin-runtime` 文件以及正式环境保持不变。

## 非目标

- 不新增一级或二级菜单。
- 不新建独立场景技能包路由组件。
- 不改变普通用户的运行调用权限。
- 不调整右侧 Agent 的 Skill 管理入口。
