# 场景技能包管理员创建能力恢复

## 已确认需求

2026-09-14，用户反馈账号菜单和 Skill Hub 的场景技能包创建流程消失，确认登录账号为 admin，并明确选择“恢复 admin 创建和编辑本人内容”。确认时说明：恢复后仍由其他管理员审核，原有四步流程不变。

## 原因与决策

当前版本把审核权限优先映射成管理员角色，并用“必须是 PM”同时控制入口、编辑、保存和提审。具有完整权限的 admin 因此失去创建能力。改为独立判断创建能力和审核能力；审核角色仍保留，但不能抵消已授予的创建及跨菜单编排权限。

- admin 的 `*` 权限以及明确具备创建、跨菜单编排权限的账号，可以新建、保存、提审和编辑本人可编辑状态的内容。
- 仅有审核权限而缺少创建或编排权限的账号，继续不能创建。普通 PM 不因此获得审核权限。
- 仅本人内容可编辑；待审核内容只读。本人创建或提交的内容仍不能本人审核，另一个具备审核权限的管理员处理。
- 保留最新试运行、引用权限、固定版本、版本冲突、发布快照和启停校验。
- 保留 PM 示例归属和既有数据迁移策略，不补造 admin 历史示例。

## 页面及范围

恢复账号菜单和 Skill Hub 的创建按钮及直接进入创建态的能力，复用场景定义、Skill 链路编排、试运行、提交审核四步。本人内容的编辑入口沿用原列表动作。文案改为当前创建人，避免仍提示“管理员只能审核”。不更改其他模块、账号角色分配、数据库、公共布局或手工维护的运行文件。

## 验收

完整权限和明确组合权限均可创建；审核权限单独存在时仍被拒绝；admin 保存后可刷新并重新编辑自己的草稿、不能编辑 PM 的内容；完成试运行后可提审，但不能自审；PM 原有流程及其他管理员审核不受影响。验证入口、四步流程、角色回归、构建和环境资源一致性。
