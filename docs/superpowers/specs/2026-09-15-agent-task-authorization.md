# AI 助手任务与批量授权交互方案

目标：把连续的“请求执行命令／授权已确认／重试说明”合并为一个可持续更新的业务任务区，让用户一次核对明确范围、批量授权、持续查看执行结果。

依据：用户提供的 aiwork.lenovo.com.cn 截图、当前服务器 Git 的工作台源码和项目 0914 UI Skill。线上页面浏览器读取超时，尚未核实其源码与当前仓库的对应关系。以下为待落地设计，不表示 aiwork 已修改。

## 推荐交互

1. 一次用户请求形成一个任务。正文只保留必要业务说明和最后结果；过程在同一任务区原地更新，不为每个工具请求和批准结果重复增加卡片。
2. 任务头显示业务名称、状态及完成数，例如“查询合作伙伴数据 · 等待授权 · 0/3”。任务进行中只展开当前步骤，已完成步骤自动收起，可查看完整过程。
3. 待授权时在该任务内展示待执行清单，每项包含业务动作、数据范围、影响和状态。支持逐项选择、全选可批量项，主按钮显示“授权选中项（N）”；未选择时不可提交，另保留拒绝选中项或取消任务。
4. 用户确认仅覆盖当前任务、当前范围及明确选中的请求集合。新增环境、数据范围、字段或操作类型不能沿用旧确认；导出、写入、发布等按原业务审批要求独立确认。界面不提供无限期自动允许所有命令。
5. 授权接受后原卡显示“已授权 N 项”，执行中的步骤单独显示“进行中”。只有真实执行结果到达才显示“已完成”。拒绝、失败、部分完成和取消有独立状态，未选中项目仍待授权。
6. 同一已授权请求的进度、工具反馈及限定范围内的重试按请求 ID 合并更新；重复事件不新增卡片，重复点击不重复执行。重试是否可继续由执行端校验有效授权决定，不靠界面隐藏弹窗。
7. 命令、namespace、接口参数及调试日志默认放到“技术详情”。用户默认看到业务说明、风险和影响范围，错误保留一行原因与可执行的下一步。
8. 成功结束后保留紧凑结果摘要和可用结果入口，执行过程折叠；任务未完成时不能以绿色“授权已确认”替代真实执行完成。

## 方案取舍

- 只折叠现有卡片：改动小，但保留错误请求关联，也不能形成真正的批量确认，不采用。
- 按任务聚合、明确清单批选、原地更新：推荐，兼顾可读性和每次授权范围。
- 整个会话自动允许所有后续调用：确认次数最少，但范围不明确且跨任务，不采用。

## 当前源码必须修正的对应关系

现有卡片仅传 command，处理函数始终寻找最新待授权消息。需要以 conversationId、taskId 和 requestId 精确关联；批量动作携带所选请求 ID 集合，不通过“最后一张卡片”推断。

当前 pending 只有一个内存槽，应改为按请求归属保存上下文。会话切换、刷新、历史恢复和过期必须可判定：历史展示记录不能自动恢复有效执行权限。未收到后台确认时，禁止直接把后端任务标记为已完成。

## 前后端分工

展示层负责任务归并、清单勾选、折叠与状态呈现。执行端负责待授权请求、操作类别、真实范围、有效期、当前权限、批准结果、执行幂等与最终状态。

当前工作台聊天接真实 /api/harness/chat，但现有结构化授权是前端本地演示；后端尚无对应的暂停／批准／批量恢复协议。因此预览实现必须清楚区分本地流程与真实执行。不能把立即执行的 /api/harness/invoke 当作授权接口，也不能解析模型文字“已批准”作为用户同意。

供线上合并时需要对接的最小对象：任务 ID、会话 ID、请求 ID、请求版本、业务说明、操作类别、参数范围摘要、状态、有效期、可批量分组；批准请求提交明确选中的 ID 与版本，响应逐项给出接受或拒绝结果。执行后再回传步骤状态。所有实际执行仍走原有权限和审批校验。

## 视觉与验收

沿用 0914 的字体、颜色、间距和圆角；以轻量任务清单与折叠过程组织内容，减少橙色大框和重复绿色回执。保留当前 AI 面板尺寸、输入区、报告展开、左导航和业务页面。

重点验证：A/B 请求点击 A 只影响 A；未选中及其他任务不被批准；批量接受与执行完成区分；重复事件和点击幂等；刷新及切会话失效处理；后台拒绝和部分成功；窄面板自然换行；键盘勾选、焦点移交、折叠状态和读屏提示；原权限、业务负责人、场景包四步与禁止自审不回退。
