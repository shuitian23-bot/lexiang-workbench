# Skill Hub 本人 Skill 编辑入口设计

## 目标

在 Skill Hub 中，为当前账号创建且不处于能力更新流程的 Skill 提供统一“编辑”入口，同时保持能力上下文受控更新、审批、发布和启停链路不变。

## 判定规则

- “我的 Skill”以 `item.owner === (user.value || 'admin')` 判断。
- 能力变化展示仍由 `capabilityUpdatePresentation(item).visible` 统一判定。
- 只有本人 Skill 且能力变化不可见时，展示一个“编辑”按钮。
- 能力变化可见时，不展示普通“编辑”；继续使用“更新”“继续更新”“正在准备”、审批更新或发布更新等受控入口。
- 非本人 Skill 不展示普通“编辑”，无论当前账号是否具有管理员权限。

## 状态行为

- 草稿、待审批、已审批、已发布、已禁用、已驳回：满足本人且无能力更新时，均展示“编辑”。
- 草稿进入原草稿恢复链路。
- 已驳回进入原驳回修改链路，保留驳回上下文。
- 其他状态进入既有普通编辑链路。
- 每行最多展示一个普通“编辑”入口，不与“返回编辑”或“被驳回去修改”重复。

## 保护范围

- 不修改 Skill 状态数据、审批权限、发布/禁用操作和能力更新状态机。
- 不修改公共导航、右侧 AI 助手、权限管理或 `admin-runtime`。
- 只调整 Skill Hub 操作列表组装与对应编辑路由参数。

## 验收标准

1. 本人所有非能力更新 Skill 均出现且只出现一个“编辑”。
2. 本人能力更新 Skill 不出现普通“编辑”，受控更新入口保持可用。
3. 非本人 Skill 不出现普通“编辑”。
4. 本人草稿点击“编辑”恢复草稿；本人驳回项点击“编辑”保留驳回修改上下文。
5. 原审批、发布、禁用、评估、测试和查看操作不回退。
