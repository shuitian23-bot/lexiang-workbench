# Skill 能力变更同步 POC 设计

## 目标

在现有 Skill Hub 与五步 Skill 创建流程中补齐能力变更的人工闭环：发现变化、定位受影响 Skill、查看差异、进入更新草稿、重新评估、审核并发布。线上版本在新版本发布前继续生效，系统不自动覆盖线上 Skill。

## 一期范围

- Skill Hub 显示独立于生命周期的能力更新状态，并支持“只看有更新”。
- 更新记录展示菜单上下文、变化类型、变化对象、前后值、检测时间、能力版本及影响说明。
- “更新”仅对创建人、负责人或管理员可见；无草稿时从线上版本创建编辑草稿，有草稿时继续原草稿。
- 更新流程复用“基础配置 -> 需求澄清 -> 草稿生成 -> 评估验证 -> 提交审核”。编辑页持续提示能力变化，但不自动勾选新增能力。
- 综合评分必须大于等于 0.80 才能提交审核。当前 0.782 阻断，AI 微调后的 0.859 放行。
- 新版本发布后，线上版本切换为编辑版本，能力更新状态清除；发布前旧线上版本持续可用。
- Skill Hub 默认展示两条 POC 能力更新记录，分别对应“产品知识问答”的接口/字段增强和“券包权益推荐”的权限变化，不再提供“模拟能力变化”入口。
- 汇总区同时保留“能力更新”和“已禁用”卡片；两张卡片均可点击筛选对应 Skill，避免能力更新统计替代原有禁用统计。
- 更新编辑页把能力上下文组织为两层信息：先展示当前已选择的能力，再展示本次变化；本次变化进一步区分“已选能力受影响”和“可选新增”。

## 数据与边界

- 本 POC 使用独立 service 层提供固定能力变化记录与版本计算，不模拟真实扫描、邮件发送、权限服务或后端持久化；固定记录作为本次 POC 的默认业务数据直接展示，不提供用户侧 Mock 开关。
- 增强、破坏性变化与权限/配置异常使用不同类型；新增独立菜单只记录发现，不自动关联 Skill。
- 生命周期状态与能力更新状态分别存储、分别展示。
- 时间统一使用 Asia/Shanghai，格式 `YYYY-MM-DD HH:mm`。
- 顶部导航、左侧导航、右侧 Agent、页签与账号区域保持现有基线。

## 交互

1. 用户进入 Skill Hub 后，“能力更新”卡片直接显示当前有变化的 Skill 数量，默认两条记录可继续后续流程。
2. 点击“能力更新”卡片，列表仅展示有更新的 Skill；点击“已禁用”卡片，列表仅展示已禁用 Skill。切换卡片时清除冲突筛选，再次点击当前卡片恢复全部列表。
3. 点击“查看变化”打开详情，逐项查看 before/after 与影响。
4. 点击“更新”进入当前 Skill 创建页；系统复用已有草稿或克隆线上版本为新编辑草稿。
5. 编辑页顶部持续显示精简的变化概览，包括已选能力受影响数量、可选新增数量、目标能力版本和检测时间；“查看能力上下文”定位到需求澄清页中的统一能力上下文模块。
6. 统一能力上下文模块先展示“已选择”，发生变化的已选能力标记“有更新”；再展示“本次变化”，分别列出“已选能力受影响”和“可选新增”。可选新增默认不勾选，用户点击“加入上下文”后才进入已选择列表。
7. 评分未达 0.80 时只能返回修改或 AI 微调；达到门槛后才可提交审核。
8. 审核发布前旧线上版本不变；新版本发布后更新状态闭环。
9. 已发布 Skill 保留“禁用”操作，已禁用 Skill 保留“启用”操作；卡片筛选不得改变 Skill 生命周期状态。

## 验收

- Skill Hub 初始显示两条能力更新，“能力更新”卡片显示 `2`，点击后筛选出对应 Skill，且生命周期状态不被“有更新”替换。
- “已禁用”卡片显示 `1`，点击后筛选出已禁用 Skill；已发布 Skill 的“禁用”和已禁用 Skill 的“启用”操作均存在。
- 变化详情字段完整，更新按钮遵循负责人/管理员权限。
- 更新草稿保留线上版本，重复点击“更新”不重复创建版本。
- 新增能力不自动进入已选上下文。
- 顶部变化提醒不重复展开变化详情；下方统一模块同时可见“已选择”和“本次变化”两层信息。
- 已选且受影响的能力显示“有更新”；未选择的新能力显示“可选新增”和“加入上下文”，加入前不得计入已选数量。
- 0.782 无法进入提交审核，0.859 可以。
- 页面不存在“模拟能力变化”和“重置演示数据”入口，用户可直接从默认能力更新记录进入后续流程。
- lint、typecheck、build、shell smoke 与本功能测试通过。
