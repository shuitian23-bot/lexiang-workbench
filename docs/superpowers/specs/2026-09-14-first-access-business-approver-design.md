# 首次登录权限申请业务负责人恢复

## 已确认问题与范围

用户截图指向 `AccessDeniedView.vue` 的首次访问权限申请，而不是后台 `AgentPermissionsView.vue`。附件 `leaibot-workbench-fork-dev-guanfeng2.zip` 已包含首次访问的业务负责人字段；9 月 10 日选择性合并明确排除了该页面，导致后台有字段、首次访问入口没有字段。恢复请求及后续“代码库里有，但是线上看不到”均针对权限管理，截图进一步明确了这个入口。

## 恢复契约

- 在基本信息中复用现有 `BusinessApproverField`；沿用五个 ITCode 选项与分组，不默认指定负责人。
- 未选或非法值阻止下一步与直接提交，回到基本信息展示错误；选择后清除字段错误。
- 确认页与成功页展示所选负责人标签。新申请同时保存 `businessApprover`、单元素 `businessOwners`、`permissionSnapshot.businessApprover`，后台沿用现有经理后转所选负责人的审批流程。
- 从前一步改选负责人后，确认及提交必须使用新选择；不根据角色 owner 自动代选，不提前开通权限。
- 已提交的历史申请保持原值和已有审批记录，不为缺少字段的旧快照补空值。租户必选、角色冲突、角色复制和重复提交保护保持有效。
- 仅改首次访问页面及权限模块内对应调整记录，新增专项回归。不引入附件的全页样式、重复弹窗指令或其他模块回退。

## 验证与发布

先证明旧代码无法通过字段/必填/提交快照回归，再实施并验证首登申请到后台审批的交接。完成工程必需检查及本地实际界面操作；真实线上只核对页面资源，不创建真实审批申请。通过隔离分支和非删除式发布更新 new、正式环境及已授权 Git 目标，分别记录版本和发布证据，保留共享运行文件与他人改动。
