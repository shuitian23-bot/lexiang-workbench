# 门户工作台双环境发布记录设计

## 目标

调整日志不再用单个“发布人”概括一次改动。每条改动分别展示 `new 预览` 和 `正式环境` 的发布结果，并保留实际发布账号、发布时间和对应版本。

## 已确认规则

- 每条改动固定展示两个环境：`new 预览`、`正式环境`。
- 已发布环境展示发布人、发布时间和版本；未发布环境明确显示“未发布”。
- 两个环境允许由不同账号、在不同时间发布。
- “发布人”只表示实际执行对应环境发布的服务器账号，不再展示“改动人”。
- 历史记录只使用可核实证据补录；无法确认的发布人显示“历史未记录”，不根据 Git 作者猜测。
- 新记录从本次起由发布脚本写入统一台账，并同步给两个环境读取。
- `new` 与正式发布仍是两个独立步骤；写入 `new` 记录不等于已发布正式环境。

## 数据边界

页面记录继续由现有调整日志数据提供标题、改动点、说明和状态。发布台账只保存以下字段：

- 记录标识
- 环境
- 发布人
- 发布时间
- 版本

页面优先读取服务器发布台账；没有台账记录时，兼容现有日志中的历史部署证据。历史记录的时间无法区分两个环境时，使用“历史时间未单独记录”，避免把一项记录的更新时间伪装成精确发布时间。

## 页面结构

每条调整日志保留标题、说明、改动点、状态和追溯信息。在内容区增加“发布记录”，用两行展示：

1. `new 预览`：发布状态、发布人、发布时间、版本。
2. `正式环境`：发布状态、发布人、发布时间、版本。

原左侧单一“发布人”字段移除，只保留该条调整记录的记录时间。发布记录使用紧凑分隔行，不新增嵌套卡片。

## 发布流程

新增独立发布记账脚本，不修改当前存在他人未提交改动的自动合并脚本。脚本执行时：

1. 从当前服务器登录账号获取发布人，允许通过明确参数覆盖。
2. 校验环境只能是 `new` 或 `formal`。
3. 在文件锁保护下读取并更新统一台账。
4. 只更新当前环境，保留同一改动另一环境已有记录。
5. 原子写入统一台账，并把同一份只读数据同步到 `new` 和正式站点。

## 失败处理

- 环境、记录标识、标题、发布人或版本缺失时拒绝写入。
- 台账 JSON 损坏时拒绝覆盖原文件并报错。
- 并发写入时等待文件锁；超时后失败，不强行覆盖。
- 页面读取台账失败时继续展示静态历史记录，不影响工作台其他功能。

## 验收标准

- 每条日志固定出现 `new 预览` 和 `正式环境`。
- 仅发布 `new` 时，正式环境显示“未发布”。
- 后续正式发布后，同一条日志补齐正式发布人、时间和版本，不新增重复改动项。
- 两个环境由不同账号发布时分别展示对应账号。
- 发布台账脚本并发安全、重复执行可更新当前环境且不丢失另一环境。
- 权限管理、右侧 AI 助手、业务页面和受保护 `admin-runtime` 文件不变。
