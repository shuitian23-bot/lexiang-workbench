# 线索池-政企与协议产品订单管理新包对齐设计

## 背景

用户提供 `_0708_analysis (3).zip`，要求在当前门户工作台基础上更新“线索池-政企”和“协议产品订单管理”。本次以压缩包内对应源码和验收脚本为目标，不整包覆盖当前项目。

## 采用方案

采用“目标模块严格对齐、其他模块保持当前版本”的方式：

- 严格采用新包中两个目标模块的字段、结构和交互。
- 只移植目标模块及必需的页面能力元数据。
- 不复制新包中的 `node_modules`、完整构建目录、旧版公共源码或其他业务模块。
- 不修改权限管理、右侧 AI 助手、公共导航、原线索池、打分模型或协议采购单管理。
- 本轮只完成隔离分支源码、构建和本地验收，不自动更新 `new`、正式环境或 GitLab。

## 线索池-政企

### 页面结构

- 保留标题“线索池-政企”和只读查询定位。
- 不展示线索统计卡、角色切换和批量业务操作。
- 工具栏保留“导出（脱敏）”和“导出（明文）”，调用新包指定的线索池公共导出链路。

### 筛选字段

按新包保留以下字段：

- 创建日期
- 线索编号
- Lenovo ID
- 手机号
- 姓名
- 客户名称
- 客户经理编码
- 线索分下限、上限
- 客户分级

移除当前新增版本中的“所属 IS”筛选。进入政企线索池时清空普通线索池中不属于该页面的隐藏筛选条件，查询和重置继续走新包指定的共享线索池筛选状态。

### 表格

政企表格独立显示：操作、ONE ID、Lenovo ID、线索编号、姓名、客户名称、手机号、客户分级、线索分、客户经理编码、REL-GAB IS、REL-KAB IS、REL-新兴市场 IS、创建时间。

不显示普通线索池的推送、分配、反馈、转商机、SQL 金额、来源、MQL、状态和所属 IS 等字段。操作列只保留“查看详情”，详情返回时回到“线索池-政企”。

### 页面能力元数据

在内容槽注册表中增加 `lead.governmentPool`，记录路由、布局、源码、共享组件候选和交互能力，避免菜单和页面能力上下文脱节。

## 协议产品订单管理

### 列表

- 保留采购单编号、订单编号、状态三个查询条件。
- 按新包移除“重置”按钮。
- 导出按钮文案改为“导出”，按新包只展示“协议产品订单导出已生成”的提示，不下载 CSV。
- 表格字段、状态和分页保持新包定义。

### 详情

- 返回按钮使用“← 返回协议产品订单管理”。
- 保留采购单基本信息、收货地址明细和商品明细。
- 收货地址明细按新包展示两个地址块。
- 详情区块标题增加新包中的蓝色引导条样式。

## 实现边界

主要修改范围：

- `vue-app/public/admin-runtime/workbench-lead.js`
- `vue-app/public/admin-runtime/workbench-agreement-orders.js`
- `vue-app/src/content-slot/contentSlotDefinitions.js`
- 两个针对新包验收规则的测试脚本
- 重新生成的 `public/admin-vue` 构建产物

菜单、路由和 Vue 包装页当前已经存在，只有当测试证明新包要求与当前定义不一致时才做最小调整。

## 验证

- 先运行新包验收测试并确认当前版本失败。
- 实现后确认两个新包验收测试通过。
- 运行现有菜单新增测试、产品契约回归、Lint、类型检查、设计规范检查和生产构建。
- 浏览器验证两个页面的列表、筛选、详情返回、地址块、按钮和 Agent 展开场景。
- 确认受保护的 `workbench-geo.js`、`workbench-pages.js` 及权限管理无差异。
