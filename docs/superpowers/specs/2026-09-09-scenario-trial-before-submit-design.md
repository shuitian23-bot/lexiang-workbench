# 场景包试运行与提交

创建流为场景定义 → Skill 链路编排 → 试运行 → 确认提交。节点无错误才能提交审核；报错节点展示原因，并可带提示返回编排页定位修改。修改后重新进入试运行。页面不提供微调或打分。权限与版本检查合并至试运行步骤并在提交时重新校验；保持其他管理员独立审核。

## 数据方式

现有场景包没有真实执行桥接；本轮按已说明的预览方案使用明确标注的模拟数据。固定 mode=simulation、executionPerformed=false，仅使用固定版本样例或用户提供的节点样例输出，绝不把预期输出当作执行结果。条件命中和确认审批为本次模拟设定，不生成真实授权票据。不调用真实业务接口。

## 状态和门槛

未试运行、报告过期、节点错误、报告未完整覆盖链路均不能提交。completed/attention 可通过，但不得有 blocked 节点；可选期望为空不算错误，提醒不等于报错。报告必须与当前定义、连线、固定版本、节点配置、所引用目录和测试请求一致。只移动画布坐标不使结果过期。试运行中的导航及提交禁用。下一步、已访问步骤跳转、最终提交、领域/store提交及重提使用同一门槛。

错误提示随 report.nodes 保留，不因返回或修改立即清空。编排节点有错误标记，选中节点属性上方显示具体错误；修改后明确这是上次提示，需重跑验证。重新试运行产生新报告后，已解决的节点错误随新结果清除。

最近一次请求与报告深拷贝保留到提交、驳回、重提与审批，管理员详情可展开逐节点输入输出；它不替代真实授权或独立审核。已发布包不原地编辑。旧记录没有报告时展示未试运行；新提交必须满足门槛。

## 设计与验证

沿用 T4 场景创建流程，复用 ContentPageHeader、SectionHeader、已有表单/按钮/token；权限检查为试运行页折叠区域。ScenarioPackageTrialPanel 和 ScenarioTestReportSummary 为场景域组合。没有微调编辑器、建议、评分或比较面板。窄内容槽支持换行和区域滚动，无页面级横向溢出；返回节点同时定位画布及外层布局。

验证未测不能前进、报错不能提交、带错误返回定位、修改后旧报告失效、重试无错误才可提交，以及节点输入/上下游/分支/样例版本/模拟票据和报告隔离。要求检查和标准桌面/Agent挤压浏览器验证通过后仅发布 new，保护 admin-runtime 和正式环境。区分模拟交互验证与公网真实执行。
