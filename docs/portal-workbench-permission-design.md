# 门户工作台权限设计框架

版本：v0.1  
适用范围：门户工作台后台，包括左侧菜单、主页面能力、右侧全局 Agent、Skills 管理与任务执行记录。  
预览环境：https://new.leaibot.cn/admin/workbench.html

## 1. 设计目标

门户工作台面向业务运营、官网平台运营、PM 和管理员。权限设计需要同时解决两类问题：

- 用户能看到哪些菜单、页面、数据和操作按钮。
- 用户能通过右侧 Agent 调用哪些 Skill，能否申请、执行、写入、发布和导出。

核心原则：

- 菜单权限和 Agent 权限解耦。
- 右侧 Agent 是全局独立模块，不因菜单变化而消失。
- Agent 可以引导申请权限，但不能绕过页面、数据和 Skill 权限。
- 写入、发布、导出等高风险动作必须二次确认并留痕。

## 2. 权限分层

### 2.1 用户与组织层

定义用户是谁，以及归属范围。

- 用户账号
- 角色
- 部门/业务线
- 所属平台
- 负责项目或渠道
- 数据范围

建议角色：

- 普通运营
- 商品运营
- 内容运营
- 会员运营
- 数据分析
- PM
- 平台管理员
- 超级管理员

### 2.2 菜单与页面层

控制用户能进入哪些模块。

结构建议：

```text
菜单组
  页面
    页面内按钮
      字段可见性
      数据范围
```

示例：

```text
乐享运营
  运营总览
  Query 分析
  质量分析
  流量分析
  GMV 分析

在职员工管理
  概览
  认证审核
```

控制方式：

- 无菜单权限：不展示左侧菜单入口。
- 有页面权限但无操作权限：页面可见，操作按钮禁用或隐藏。
- 无字段权限：字段脱敏、隐藏或展示占位。

### 2.3 数据权限层

控制用户能查看和操作的数据范围。

常见范围：

- 全平台
- 单业务线
- 单渠道
- 单项目
- 本人负责
- 本人创建

数据权限必须同时作用于页面和 Agent。  
例如用户只能看会员业务数据，Agent 在回答 GMV 或导出数据时也只能使用该范围。

### 2.4 Agent 与 Skill 层

右侧 Agent 全局可见，但能力由 Skill 权限控制。

Skill 状态建议：

- 可用的：用户已获得权限，可直接调用。
- 可申请的：用户暂未获得权限，但可以提交申请。
- 待审批：用户已提交申请，等待 PM 或管理员处理。
- 禁用的：当前 Skill 停用，用户只能查看原因。
- 管理员配置：普通用户可见说明，管理员/PM 可配置参数、审批规则和风险等级。

Skill 分类建议：

- 数据分析类
- 内容运营类
- 商品运营类
- 活动运营类
- 用户/会员类
- 平台配置类
- 质量巡检类
- 知识问答类

## 3. 操作风险等级

Agent 和页面操作都应设置风险等级。

| 等级 | 类型 | 示例 | 控制方式 |
| --- | --- | --- | --- |
| L1 | 只读分析 | 解读指标、查询知识库 | 直接执行 |
| L2 | 内容生成 | 生成报告、生成文案 | 可编辑后使用 |
| L3 | 草稿配置 | 生成商品配置草稿、活动配置草稿 | 保存草稿，不直接发布 |
| L4 | 写入配置 | 修改商品配置、修改页面模块 | 二次确认 |
| L5 | 发布上线 | 发布活动页、上线配置 | 二次确认 + 审批 |
| L6 | 敏感导出 | 导出用户、订单、认证数据 | 权限校验 + 审批 + 留痕 |

## 4. 关键流程

### 4.1 登录与初始化

```text
用户登录
  获取用户身份
  获取角色
  获取菜单权限
  获取数据范围
  获取可用 Skill 清单
  渲染左侧菜单
  初始化右侧 Agent
```

### 4.2 页面访问流程

```text
用户点击菜单
  校验页面权限
    有权限：进入页面
    无权限：不展示入口或展示无权限提示
  校验页面按钮权限
    有权限：按钮可操作
    无权限：按钮隐藏或禁用
  应用数据范围
```

### 4.3 Agent 调用 Skill 流程

```text
用户在底部输入框提交任务
  Agent 识别任务意图
  匹配 Skill
  校验 Skill 权限
    可用：继续
    可申请：引导申请
    待审批：展示审批状态
    禁用：展示禁用原因
  校验数据范围
  判断风险等级
    低风险：执行并返回结果
    高风险：展示影响范围与变更摘要
  用户二次确认
  执行任务
  写入任务记录
```

### 4.4 Skill 申请流程

```text
用户进入 Skills 管理
  查看可用/可申请/待审批/禁用 Skills
  选择申请 Skill
  填写申请原因、使用场景、数据范围
  提交审批
  PM/管理员审批
    通过：加入可用 Skills
    驳回：展示原因
    调整范围：授予部分权限
```

### 4.5 高风险操作确认流程

```text
Agent 检测到写入、发布或导出
  展示操作摘要
  展示影响范围
  展示回滚或撤销方式
  要求用户确认
  必要时进入审批
  执行后写入任务记录
```

## 5. 任务记录与审计

所有 Agent 写入类动作都要记录。

建议字段：

- 任务 ID
- 任务名称
- 执行人
- 执行时间
- 关联 Skill
- 操作对象
- 数据范围
- 风险等级
- 审批人
- 执行结果
- 变更前摘要
- 变更后摘要
- 回滚记录

## 6. 页面建议

### 6.1 权限管理页

面向管理员/PM。

模块：

- 用户管理
- 角色管理
- 菜单权限
- 页面操作权限
- 数据范围
- Skill 权限
- 审批规则
- 审计记录

### 6.2 Skills 管理页

面向普通运营、PM 和管理员。

普通运营可见：

- 我可用的
- 可申请的
- 待审批
- 禁用的
- 使用记录

PM/管理员可见：

- Skill 配置
- 审批规则
- 风险等级
- 数据范围
- 禁用/启用
- 执行历史

## 7. 实施顺序

建议分三期推进。

### 一期：权限骨架

- 菜单权限
- 页面权限
- Skill 状态展示
- Skill 申请入口
- Agent 调用前权限判断

### 二期：风险控制

- 写入类二次确认
- 任务记录
- 审批流
- 数据范围控制

### 三期：管理后台

- 角色配置
- 菜单/页面/按钮权限配置
- Skill 参数配置
- 审计与回滚

## 8. 不建议的做法

- 不要只做菜单权限，忽略 Agent 权限。
- 不要让 Agent 绕过页面和数据权限。
- 不要把 Skill 创建流程塞进右侧 Agent 面板。
- 不要把高风险写入做成一句话直接执行。
- 不要让禁用 Skill 完全消失，应展示原因或申请路径。

## 9. 当前产品规则

- 右侧 Agent 是门户工作台全局模块。
- Agent 任务交互主要发生在底部输入框。
- Skills 管理通过右侧 `管理技能` 入口进入主页面。
- 普通运营可以查看和申请 Skills。
- PM/管理员可以配置、审批、禁用和审计 Skills。
