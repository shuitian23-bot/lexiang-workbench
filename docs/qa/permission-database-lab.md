# 权限数据库隔离联调

## 范围和保护边界

本轮为本地联调，不是线上发布。采用现有 Express、SQLite、bcrypt、Vue 依赖，不新增生产依赖。

- 后台入口：`scripts/run-permission-lab.cjs`。不导入 `db/schema.js`、`server.js` 或真实环境配置，不读取/复制真实账号密码，不加载真实邮件服务。
- 首次启动只在系统临时目录新建 `leaibot-permission-lab-*/permission-lab.sqlite`。重新打开必须指定该工具创建的专用文件，并通过路径、标记和表检查。禁止用真实数据库路径代替。
- 后台只绑定 `127.0.0.1`，默认 3317；前端另起 5180，所有 `/api` 请求仅指向该测试服务，未知接口直接拒绝，不回退真实后台。
- 管理员登录使用 bcrypt；三个固定的非管理员演示账号支持空密码登录，仅存在于本地隔离服务。所有登录使用独立 `permission_lab_3317` Cookie，未复用原 `connect.sid`。服务端每次操作复核账号状态，受限会话不自动升级为管理员/工作台会话。其他账号、管理员或错误入口不因空密码放行。
- 无账号审批凭证随机生成、按申请/节点/收件人/版本绑定、7 天有效。数据库保存校验摘要，原始凭证仅保存在受管理员访问控制的模拟收件箱；不真实发送邮件。
- 保留原正常管理员服务、原前端入口和原浏览器演示模式；新前端模式只在开发环境生效，不会通过生产构建启用。
- 本地隔离模式的 admin 同样保留原 POC 的 7 个模块、5 类申请、编辑操作、记录和演示身份切换。原管理操作/申请继续保存到浏览器演示数据，隔离账号申请/审批保存到 SQLite；列表标注来源，刷新不会用数据库列表覆盖原浏览器审批。原正常后台的认证及授权不变。
- `noaccess`、`internal-disabled`、`external-disabled` 是新增场景的保留测试身份；代为启用这些身份必须走隔离 API。原浏览器演示用户（包括原管理列表中的 admin）的启用沿用原本地流程，不改变后台登录账号。切换演示身份不能代替数据库审批人的真实登录身份。

## 启动

环境：Node 20.20+（与本机 SQLite 原生依赖 ABI 一致），安装仓库已有根依赖、Vue 开发依赖；不新增软件包。仅浏览器测试需要 Playwright，可通过 `PLAYWRIGHT_MODULE_PATH` 指定已安装位置。

在项目根目录设置本次隔离库密码后启动：

```powershell
$env:PERMISSION_LAB_ADMIN_PASSWORD = '<本地测试管理员密码，至少12位>'
$env:PERMISSION_LAB_DEMO_PASSWORD = '<本地测试账号密码，至少12位>'
node scripts/run-permission-lab.cjs
```

密码不得使用真实账号密码，不写入仓库。启动输出独立数据库路径；保存此路径可保留演示结果。

另一个终端在 `vue-app` 中运行：

```powershell
$env:VITE_PERMISSION_LAB = 'true'
$env:VITE_AUTH_MODE = 'server'
node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5180 --strictPort
```

前端入口为本机 5180 的 `/admin-vue/login`。默认后端端口 3317 和前端 origin 5180 配对。勿复用正在运行的正常服务端口。现阶段只在本机使用，禁止映射到公网。

保留原状态重启：将 `PERMISSION_LAB_DB` 设置为首次启动输出的完整文件路径，再运行后台命令。恢复初始演示：停止本次测试服务，清除 `PERMISSION_LAB_DB` 后重新启动，生成全新隔离库；旧库保留，不执行删除或重置真实数据。重启后登录会话失效，重新登录即可，申请记录保留。

## 四场景演示

| 账号 | 入口 | 初始状态与预期 |
|---|---|---|
| admin | 外部用户登录 | 隔离测试管理员，正常密码认证；审批列表可处理系统管理员节点 |
| noaccess | 内部用户登录 → ADFS 表单 | 启用但无工作台权限，提交首次权限申请，直线经理为 poc-manager |
| internal-disabled | 内部用户登录 → ADFS 表单 | 禁用且保留原权限，进入启用申请；管理员批准后重新登录 |
| external-disabled | 外部用户登录 | 禁用，提示联系联想业务接口人，不跳转自助启用 |
| poc-manager | 无账号、不能登录 | 管理员在申请详情打开“审批邮件演示”，点击邮件单号进入独立审批页 |

除 `admin` 外，表内三个可登录演示账号只需输入账号名并点击登录；匹配后不显示密码字段。`admin` 仍使用初始化时配置的管理员密码。数据库保留原密码散列（不写入源码），不重置已完成审批或启用状态；新建演示库仍需提供初始化密码。

建议申请人和管理员使用两个浏览器会话（例如普通窗口和无痕窗口）。经理的邮件链接可以复制到全新会话打开。该身份没有登录密码或工作台账号。

首次访问审批为“申请人直线经理 → 所选业务负责人 → 自动生效”；业务负责人同样可通过模拟邮件审批，所属组织仍必填。新增模拟邮件可在管理员申请详情再次点击“审批邮件演示”查看。账号启用为“申请人提交 → 系统管理员审批”，不会清除或替换原权限。

## 复验

```text
node --test scripts/permission-lab.test.cjs
node scripts/permission-lab-browser.cjs
```

两者自行新建测试数据库，不接触演示库。浏览器测试使用单独的 3318/5181 端口和真实 HTTP/SQLite，无 API 拦截；完成后关闭其服务并清理自己生成的测试库。截图保留在命令输出的临时证据目录。

- 免密改动后的完整浏览器联调再次通过，覆盖空密码进入三个场景、演示账号切回普通账号恢复密码框、管理员空/错密码拒绝，以及审批生效后免密重新登录。原正常登录和 preview 隔离浏览器回归通过，类型检查、lint、设计守卫、Shell smoke 和临时目录构建通过。
- 四场景真实浏览器联调全部通过：首次申请入库、无账号经理和业务负责人跨会话审批、申请生效后重新登录、内部账号启用及外部禁用提示。使用真实本地 HTTP/SQLite，不拦截 API 返回模拟结果。
- 浏览器检查覆盖 1440×900、1280×720、390×844；首次申请结果、无账号审批、外部禁用提示均通过页面无横向溢出断言，并保留截图。

## 尚未纳入本轮

- 企业 ADFS/SSO 仍未对接；现有 ADFS 外观页面在此使用本地密码认证，不声称真实 SSO 已完成。
- 无真实邮件、线上数据库迁移、线上账号造数或部署；生产审批访问控制、令牌重发/撤销、持久会话等需在正式后端集成阶段确认。
- 本地后台目前只服务上述账号状态、申请与审批。其他业务 API 不代理真实服务；不会把测试授权直接写入现有生产角色表。
- 本机模拟管理员不是真实线上管理员账号，密码独立；原管理员入口继续使用原服务与原密码。
