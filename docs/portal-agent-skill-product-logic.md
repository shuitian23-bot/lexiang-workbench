# 门户工作台 Agent / Skill 产品逻辑说明

版本: 20260529-agent-skillrules1

适用范围: 门户工作台右侧 AI 助手、技能管理弹层、技能包、Skill 能力、任务调用与审批留痕。

## 1. 产品定位

门户工作台的右侧 AI 助手是全局 Agent 工作区，独立于左侧菜单和中间业务页面。无论用户当前打开运营总览、Query 分析、质量分析、GEO 看板还是在职员工管理，右侧 Agent 都保持独立运行，不覆盖、不替换、不强制跳转当前菜单页面。

Agent 的核心目标是降低运营、业务、销售使用后台能力的门槛。用户不需要理解底层接口、字段、流程编排，只需要通过底部输入框描述任务，Agent 负责识别意图、匹配技能包、拆解 Skill 能力、完成风险校验，并在必要时发起二次确认或审批。

## 2. 名词定义

### 2.1 技能包

技能包是面向普通使用者的低门槛入口，通常由一个或多个 Skill 能力编排而成。

示例:

- 经营指标解读: 读取页面上下文、查询指标、生成结论和建议。
- 商品配置助手: 校验商品配置、提示风险、在确认后写入配置。
- 内容发布检查: 检查 CMS 内容、活动页文案、链接和发布风险。
- 认证失败用户导出: 申请通过后导出认证失败用户清单。

技能包解决的是“用户想完成什么工作”。它的命名应该接近业务任务，而不是底层接口名。

### 2.2 Skill 能力

Skill 能力是底层最小能力单元，可以被技能包编排，也可以被右侧 AI 助手根据自然语言任务自动匹配调用。

示例:

- `metric.gmv.query`: 查询 GMV 指标。
- `context.page.read`: 读取当前页面上下文。
- `product.config.validate`: 校验商品配置。
- `product.config.write`: 写入商品推荐位配置。
- `cert.user.export`: 导出认证失败用户。

Skill 能力解决的是“系统实际调用什么能力”。它需要标明输入、输出、调用方式、风险等级、状态和被哪些技能包引用。

### 2.3 技能包与 Skill 能力关系

一个技能包可以编排多个 Skill 能力；一个 Skill 能力也可以被多个技能包复用。

例子:

- 经营指标解读 = 读取当前页面上下文 + 查询 GMV 指标 + 查询知识库 + 生成指标结论。
- 商品配置助手 = 校验商品配置 + 写入商品推荐位配置 + 创建审批任务。
- 认证失败用户导出 = 校验权限 + 创建审批任务 + 导出认证失败用户。

## 3. 入口与页面结构

### 3.1 右侧 AI 助手

右侧 AI 助手保留现有布局:

- 顶部: AI 助手标题、管理技能入口、新建对话、关闭。
- 中部: 场景快捷按钮、阶段目标、对话结果。
- 底部: 输入框和发送按钮。

所有任务调用都优先通过底部输入框触发。页面中不再放大段说明文案，不把 Agent 自己的全局定位直接写在右侧面板里。

### 3.2 管理技能入口

右侧 AI 助手顶部提供“管理技能”按钮。点击后打开一个新的整页弹层，底层保留当前业务页面，不切换当前菜单，不覆盖功能菜单。

管理技能弹层包含两层:

- 技能包: 面向运营、业务、销售使用和申请。
- Skill 能力: 展示底层能力、风险、状态、输入输出和引用关系。

## 4. 技能包状态规则

技能包状态面向普通用户展示，表达“我能不能用这个技能包，以及下一步能做什么”。

### 4.1 可用的

含义: 当前用户已拥有该技能包的使用权限。

用户动作:

- 点击“使用”后，关闭管理弹层。
- 右侧 AI 助手输入框自动进入该技能包任务上下文。
- 用户继续补充目标、时间范围、业务线等参数。

### 4.2 可申请的

含义: 当前用户暂未拥有该技能包，但允许提交申请。

用户动作:

- 点击“申请”后，由右侧 AI 助手引导填写申请原因、使用场景、所属组织、预计影响范围。
- 申请提交后进入待审批状态。

### 4.3 待审批

含义: 用户已提交申请，审批尚未完成。

用户动作:

- 点击“查看进度”后展示申请单状态、当前审批人、提交时间、预计处理节点。
- 在审批通过前不能直接执行该技能包。

### 4.4 禁用的

含义: 技能包当前被平台停用，可能因为风险策略、能力下线、配置调整或依赖不可用。

用户动作:

- 点击“查看原因”展示禁用原因和预计恢复方式。
- 普通用户不能申请或使用。

### 4.5 管理员配置

含义: 技能包涉及权限策略、发布规则、审批链路或平台级配置。

用户动作:

- 普通用户只看到状态和说明。
- 管理配置入口后续按权限模型开放，不在当前第一版中展开。

## 5. Skill 能力状态规则

Skill 能力状态面向产品和系统解释“这个底层能力当前能否被调用，以及调用前需要什么控制”。

### 5.1 启用

含义: 能力可被技能包或自然语言任务触发。

规则:

- 只读查询、上下文读取、草稿生成类能力一般为启用。
- 启用不代表跳过风险校验；它只代表能力本身在线且当前允许进入调用流程。

### 5.2 受控

含义: 能力可以被触发，但执行前必须经过二次确认，并生成操作留痕。

适用场景:

- 写入配置。
- 修改推荐位。
- 调整页面展示内容。
- 触发影响业务结果但不一定需要上级审批的动作。

用户体验:

- Agent 先展示“将要修改什么、影响范围、回滚方式”。
- 用户点击确认后才执行。
- 执行结果进入任务记录。

### 5.3 审批

含义: 能力需要审批通过后才能执行。

适用场景:

- 导出用户清单或敏感数据。
- 批量变更。
- 发布类动作。
- 跨组织或高影响范围操作。

用户体验:

- Agent 不直接执行。
- Agent 自动生成审批任务，带上申请人、原因、影响范围、数据范围和关联技能包。
- 审批通过后再执行，执行过程和结果留痕。

### 5.4 停用

含义: 能力暂不可调用。

适用场景:

- 依赖接口下线。
- 风控策略调整。
- 数据源异常。
- 管理员主动停用。

## 6. 风险等级规则

页面中的 `L1` 到 `L6` 是内部风险分层编码，不是用户理解成本最低的展示名称。界面上应优先展示中文风险名称，内部保留风险码用于规则判断、日志和审批策略。

风险等级不是随意编号，取值依据三类因素:

- 是否读取或写入数据。
- 是否影响线上页面、配置或用户可见结果。
- 是否涉及用户敏感信息、批量操作或跨组织影响。

### 6.1 L1 低风险

范围:

- 只读查询。
- 页面上下文读取。
- 知识库问答。

控制规则:

- 可直接响应。
- 不写入业务系统。
- 需要记录查询来源和引用结果。

示例:

- 查询 GMV 指标。
- 读取当前页面上下文。
- 查询知识库。

### 6.2 L2 内容生成

范围:

- 生成报告草稿。
- 生成文案建议。
- 生成配置建议但不落库。

控制规则:

- 可直接生成。
- 结果需要用户自行确认后使用。
- 不直接写入线上配置。

示例:

- 生成运营报告草稿。
- 生成活动复盘建议。

### 6.3 L3 流程动作

范围:

- 创建任务。
- 创建审批单。
- 发送通知。
- 写入任务记录。

控制规则:

- 可以执行流程动作。
- 需要记录发起人、任务摘要和关联上下文。
- 不直接修改线上业务配置。

示例:

- 创建审批任务。
- 创建问题跟进任务。

### 6.4 L4 受控写入

范围:

- 修改推荐位。
- 修改商品配置。
- 修改页面展示配置。

控制规则:

- 执行前必须二次确认。
- 必须展示变更前后差异、影响范围和回滚方式。
- 必须写入任务执行记录。

示例:

- 写入商品推荐位配置。

### 6.5 L5 发布变更

范围:

- 发布页面。
- 批量生效。
- 灰度切换。
- 回滚线上配置。

控制规则:

- 默认需要二次确认。
- 根据组织、页面等级和影响范围决定是否升级审批。
- 必须有发布记录和回滚路径。

### 6.6 L6 高敏审批

范围:

- 用户数据导出。
- 敏感信息查看。
- 跨组织数据访问。
- 高影响批量操作。

控制规则:

- 必须审批。
- 必须记录申请原因、数据范围、审批人、执行人和下载/导出结果。
- 不允许通过“试调用”直接执行。

示例:

- 导出认证失败用户。

## 7. 试调用规则

“试调用”不是直接执行能力，也不是绕过权限的入口。它是一个低风险的体验入口，用来让用户理解某个 Skill 能力如何被 Agent 使用。

### 7.1 试调用适用场景

- 用户不确定某个 Skill 能力能做什么。
- 用户想知道调用前需要哪些参数。
- 产品或运营想验证技能包编排是否合理。
- 用户想从能力卡片进入右侧 AI 助手，继续用自然语言补充任务。

### 7.2 试调用交互

点击“试调用”后:

- 管理技能弹层关闭。
- 右侧 AI 助手输入框进入该 Skill 能力上下文。
- Agent 先说明适用场景、所需参数、风险等级和下一步确认方式。
- 对 L4/L5/L6 能力，Agent 只能解释和收集参数，不直接执行。

### 7.3 试调用不做什么

- 不直接写入配置。
- 不直接导出用户数据。
- 不跳过审批。
- 不改变当前中间业务页面。
- 不绕过技能包申请规则。

## 8. 自然语言调用流程

完整调用链路:

1. 用户在右侧 AI 助手底部输入任务。
2. Agent 读取当前页面上下文、用户角色、组织、菜单、筛选条件。
3. Agent 识别用户意图。
4. Agent 匹配可用技能包。
5. 如果没有可用技能包，提示申请或换用可用能力。
6. Agent 将技能包拆解为一个或多个 Skill 能力。
7. 系统检查 Skill 能力状态和风险等级。
8. L1/L2 可直接生成结果。
9. L3 可创建任务或流程记录。
10. L4/L5 进入二次确认。
11. L6 进入审批。
12. 执行后写入任务记录，包括执行人、时间、技能包、Skill 能力、输入参数、输出结果和审批信息。

## 9. 任务记录规则

任务记录用于追踪 Agent 帮用户做过什么，尤其是配置、发布、审批和导出动作。

建议记录字段:

- 任务名称。
- 发起人。
- 所属组织。
- 当前页面。
- 技能包。
- Skill 能力。
- 风险等级。
- 输入参数。
- 执行动作。
- 状态。
- 审批单号。
- 执行时间。
- 结果摘要。
- 回滚或复查入口。

## 10. 权限与审批的当前边界

当前第一版先做展示和交互验证，不把 Skill 能力管理权限固定为 PM 管理。

当前确定:

- 普通运营可以查看技能包。
- 普通运营可以查看和申请可申请技能包。
- 普通运营可以看到 Skill 能力的展示信息，用于理解能力来源和调用边界。
- 高风险 Skill 能力不因可见而可直接执行。
- 写入类能力必须二次确认。
- 敏感导出类能力必须审批。

后续待补:

- 谁可以创建 Skill 能力。
- 谁可以维护 Skill 能力参数。
- 谁可以把 Skill 能力编排进技能包。
- 技能包申请审批链路如何按组织架构、业务线和官网平台 top 权限流转。
- 组织架构变更后，技能包权限和审批人如何自动同步。

## 11. 页面文案规则

为了降低业务用户理解成本，页面文案遵循以下规则:

- 对普通用户展示“技能包”和“Skill 能力”。
- 不再裸露“原子能力”作为按钮名称。
- 风险码可以保留在角标里，但主文案使用“低风险、内容生成、流程动作、受控写入、高敏审批”等中文说明。
- “启用、受控、审批、停用”必须有解释，不作为孤立标签出现。
- 写入和导出类动作的按钮文案不能暗示会立即执行。
